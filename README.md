# SV20 / проект «610» — реверс-инжиниринг геометрии корпуса

Восстановление 3D-геометрии спортивной килевой яхты SV20 (проект «610»,
конструктор Михаил Тихонов, верфь «Ракета-Яхтс») по открытым данным.
Две цели: корпус для гидродинамических симуляций и, в перспективе,
game-ready модель.

## Состояние

| Этап | Что делает | Статус |
|---|---|---|
| **Ф0** | Векторный PDF → полилинии → миллиметры в судостроительных координатах | готово |
| **Ф1** | Жёсткий каркас: линия борта, форштевень, транец, днище в ДП | готово |
| **Ф2** | Параметрический генератор обводов + гидростатика | готово |
| **Ф3** | Подгонка всех законов под гидростатику, форму и плавность | готово |
| Ф4 | Сверка с фотографиями (camera matching) | ждёт кадров |
| **Ф5** | Киль, бульб, руль | готово |
| **Ф6** | Выгрузка отдельных тел и физического манифеста | готово |

## Запуск

```bash
make          # всё: обводы, просмотрщик, выгрузка, симулятор
open viewer/index.html      # реконструкция геометрии
open sim/index.html         # симулятор управления
open sim/selftest.html      # самотест физики без сцены
```

Ф3 — отдельная цель, потому что оптимизатор считает минут пять:

```bash
python3 -m venv .venv && .venv/bin/pip install numpy scipy   # один раз
make fit      # -> out/params.json, дальше build_hull подхватит их сам
```

По шагам:

```bash
python3 scripts/extract.py        # Ф0-Ф1 -> out/frame.json, drawing.json, report.md
.venv/bin/python scripts/fit_hull.py  # Ф3 -> out/params.json, fit.md
python3 scripts/build_hull.py     # Ф2    -> out/hull.json, hull.md
python3 scripts/build_viewer.py   #       -> viewer/index.html
```

**Разбор чертежа, генератор обводов и гидростатика работают на голой
стандартной библиотеке.** Сплайны и интегралы написаны здесь же: при такой
параметризации сечения считаются по контуру аналитически, и своя реализация
выходит и точнее, и быстрее универсальной. Внешнее нужно только в двух местах:
`scipy.optimize.least_squares` для Ф3 и вендоренный three.js для просмотрщика
(`viewer/vendor/`, см. README там же). Каталог `out/` и собранный
`viewer/index.html` не коммитятся: восстанавливаются командой `make`.

## Что получилось на Ф0–Ф1

Чертёж `data/raw/610.pdf` оказался **векторным** — 7653 полилинии, 32881 точка,
нарисовано операторами `m`/`l`/`h`/`re` без кривых Безье и без матриц
трансформации. Координаты берутся из файла как есть, без аппроксимации.

Масштаб **14.3072 мм/пт** привязан к габаритной длине 6100 мм и проверяется
величинами, которые в привязке не участвовали:

| Проверка | Чертёж | Паспорт | Отклонение |
|---|---:|---:|---:|
| Ширина по палубе | 2199.9 мм | 2200 мм | −0.00% |
| Надводный борт в носу | 750.3 мм | 750 мм | +0.04% |
| Надводный борт в корме | 563.1 мм | 560 мм | +0.56% |

Ключевая тонкость привязки: у 610 **обратный наклон транца** (9.2°), и его
нижняя кромка уходит в корму на 81 мм дальше, чем кормовой конец линии борта.
Если мерить габарит по линии борта, весь чертёж съезжает на 1.3%.

Полный разбор — в `out/report.md`, интерактивно — в `viewer/index.html`.

## Главный пробел

**Ниже КВЛ на чертеже нет ни одной линии** — это проверяется кодом, а не
декларируется: перебираются все полилинии листа, из них исключаются штамп и
рамка, и в габарите корпуса ниже КВЛ не остаётся ничего. Значит нет:

- формы шпангоутов, килеватости, скулы, развала бортов;
- киля, бульба;
- пера руля ниже КВЛ.

Но кое-что приложения всё же оставили выше КВЛ — см. Ф5.

Отсюда рамка задачи: **надводная часть — это обмер, подводная — проектирование
заново под ограничения.** Известные ограничения: водоизмещение 590 кг серийной
лодки (объём 0.576 м³ в морской воде), осадка корпусом 150 мм, балласт 250 кг,
LWL 5469 мм снята с чертежа.

## Что получилось на Ф2

Шпангоут — составная кривая: днищевая панель от киля до скулы, бортовая от
скулы до линии борта, между ними сопряжение переменного радиуса. По длине
меняются пять законов (килеватость, положение скулы, погибь каждой панели,
скругление скулы) плюс линия киля в ДП. Границы с Ф1 входят жёстко и не
подгоняются.

Скула появилась не для красоты. Первая версия описывала шпангоут одной
кубической кривой и упиралась в **435 кг вместо 590**: единственная кубика не
держит одновременно длинное плоское днище и высокий борт, и ватерлиния
выходила вдвое уже нужного. Чтобы посадить 590 кг на 150 мм осадки при ширине
по палубе 2200 мм, борт обязан ломаться примерно на уровне воды — то есть
лодка чинёная, как и положено глиссирующему спортботу.

На Ф2 водоизмещение сводилось к цели **одним числом** — общим множителем
килеватости — просто чтобы проверить, что параметризация вообще накрывает
нужную форму.

## Что получилось на Ф3

48 параметров, 124 невязки, `scipy.optimize.least_squares` с ограничениями.
Невязки трёх сортов, и каждая честно подписана, откуда взялась:

- **цели** — водоизмещение 590 кг и осадка корпусом 150 мм. Это данные;
- **коридоры** — Cp, Cm, Cwp, положение ЦВ. Это не измерения, а рамка
  правдоподобия для спортбота такого размера. Штраф только за выход;
- **плавность** — изменение кривизны у кривой площадей и линии киля. Именно
  изменение, а не сама кривизна: вторая разность тянула бы килевую линию к
  прямой и записывала бы законную кривизну в невязку.

Плюс два априорных условия, которые для глиссирующего корпуса выполняются
почти всегда: килеватость растёт к носу, скула к носу поджимается.

| | Ф2 | Ф3 | Цель или коридор |
|---|---:|---:|---|
| Водоизмещение | 400 кг | **590** | 590 кг |
| Осадка корпусом | 153 мм | **150** | 150 мм |
| Ширина по КВЛ | 1600 мм | 1757 | — |
| Смоченная поверхность | 5.60 м² | 6.79 | — |
| ЦВ от кормы | 38.2% LWL | 44.0 | 44–50% |
| Cp | 0.551 | 0.525 | 0.52–0.62 ✓ |
| Cm | 0.528 | 0.760 | 0.55–0.80 ✓ |
| Cwp | 0.619 | 0.680 | 0.68–0.82 ✓ |

Стоимость 749.08 → 0.0071, то есть все условия выполнены практически точно.

**Где результат держится на предположении, а не на данных.** Cwp и положение ЦВ
легли ровно на нижнюю границу своих коридоров. Значит их определила не
гидростатика, а моя рамка правдоподобия: обводы «хотят» ЦВ дальше в корму и
ватерлинию поуже, и упираются в границу. Если рамка неверна — форма поедет
именно здесь. `out/fit.md` выписывает такие места отдельным разделом
автоматически.

## Что получилось на Ф5

Оказалось, что про киль данных заметно больше, чем я думал. На виде сверху
вычерчен **колодец, а внутри него — сечение пера в натуральную величину**:

| Что снято с чертежа | Значение |
|---|---|
| Хорда пера киля | 351.1 мм |
| Толщина | 53.8 мм, 15.3% хорды |
| Максимум толщины | 41.6% хорды от передней кромки |
| Семейство профиля | NACA 64/65, ламинарная серия |
| Положение | X = 3045 мм, ровно 49.9% LOA |
| Колодец | 410 × 105 мм |
| Гудгенсы руля | Z = 112 и 412 мм над КВЛ |
| Ось баллера | X = −27.9 мм, вертикальная |

Максимум толщины на 42% хорды — это подпись ламинарного профиля; у обычной
четырёхзначной серии он на 30%. То есть сечение киля не подбиралось, а снято.

**Колодец длиннее хорды всего на 59 мм.** Значит перо не откидывается назад,
а ходит вертикально — и сечение по всей длине подъёма обязано быть
постоянным. Вопрос о сужении пера снимается: его нет.

Дальше уже проектирование под ограничения (250 кг балласта, осадка 1.55 м):
перо 0.463 м² с удлинением 3.75, свинцовый бульб ⌀167 × 999 мм на 152 кг,
ЦТ балласта на 1052 мм ниже КВЛ. Руль — 0.250 м² по оси, снятой с транца.

Деление 250 кг между пером и бульбом зависит от того, из чего перо сделано,
поэтому `out/hull.md` печатает таблицу чувствительности. Из неё сразу видно,
что сплошная стальная плита отпадает: она съедает 217 кг и оставляет бульбу
тридцать три, что бессмысленно.

## Что получилось на Ф6

Тела выгружаются **раздельно** — корпус, перо киля, бульб, руль. Для реального
времени так и надо: каждое приложение считается своим, подъёмная сила и
сопротивление крыла берутся по его собственным площади, размаху и углу атаки.
Сшивать всё в одну оболочку имело бы смысл для RANS, но не здесь.

| Тело | Треугольников | Замкнуто | Масса |
|---|---:|---|---:|
| `hull` | 27 072 | да | — |
| `hull_lod1` | 7 668 | да | — |
| `keel_fin` | 2 604 | да | 84 кг |
| `bulb` | 1 560 | да | 163 кг |
| `rudder` | 2 604 | да | 6 кг |

Форматы: **GLB** (glTF 2.0 — Godot, Unity, Unreal, three.js берут без
конвертации), OBJ и по STL на тело. Экспорт в метрах с осью Y вверх, как ждут
движки; внутренняя судостроительная система не менялась. Писатель glTF свой:
это заголовок, JSON-кусок и бинарный кусок, ради двух сотен строк тащить
библиотеку незачем.

Рядом лежит `sv20.json` — манифест с тем, что нужно физике, а не картинке:
масса, центр тяжести и тензор инерции каждого тела, площади и удлинения крыльев,
линия четверти хорды киля и ось баллера (к ним прикладываются силы), плюс
гидростатическая таблица «осадка → водоизмещение и площадь ватерлинии», чтобы
движку не интегрировать сетку на каждом шаге.

**Сходятся два независимых пути.** Объём под КВЛ, посчитанный по сетке через
теорему Гаусса, — 0.57418 м³; посчитанный по шпангоутам интегрированием
площадей — 0.57560 м³. Расхождение **−0.25%**, и это разница дискретизации.
Значит ни в сетке, ни в гидростатике грубой ошибки нет.

## Палуба и период качки

Палуба построена по чертежу с двух видов. **Сверху** сняты комингс кокпита
(обе грани), кромка рецесса и носовая переборка — три зеркальные пары длинных
кривых от транца до X = 3350 и поперечная линия там же. **Сбоку** сняты высоты:
силуэт над линией борта даёт верх комингса в корме (+15 мм у транца, +30 мм у
переборки) и погибь палубы в носу (+45 мм на X = 3866, сходящая к +2 мм у
форштевня).

Тонкость: в корме силуэт показывает не палубу, а верхнюю огибающую всего, что
там торчит. Палуба обязана быть под ней, поэтому в корму от переборки погибь
берётся долей от снятой огибающей (`DECK["aft_crown_of_coaming"]`). Это не
подгонка, а следствие того, что проекция даёт границу сверху, а не саму линию.

Назначенным остался только уровень пайола (+180 мм над КВЛ, чтобы кокпит был
самоотливным). Раньше назначались ещё погибь и комингс — теперь они сняты, и
палуба вышла заметно площе: погибь 10–36 мм вместо 50–100.

Кокпит сходит на нет за 220 мм перед переборкой — так поверхность остаётся
непрерывной, а сетка замкнутой. Внутренний объём корпуса из-за рецесса упал
с 6.56 до 5.07 м³; объём под КВЛ не изменился.

**Период бортовой качки — 2.40 с** при GM 2127 мм и моменте инерции
1433 кг·м². Это единственная величина во всём проекте, которую можно
проверить не чертежом, а памятью, поэтому во вьювере она под ползунками:
плотность пера киля, масса и ЦТ рангоута, экипаж на борту, присоединённая
инерция. Кнопка «Качать» раскачивает модель вокруг продольной оси через ЦТ
с этим самым периодом — число становится видимым.

Что на что влияет:

| Изменение | Период |
|---|---:|
| по умолчанию | 2.40 с |
| экипаж 3 человека на борту | 2.50 с |
| перо киля из сплошной стали | 2.33 с |
| рангоут 85 кг вместо 45 | **3.13 с** |

Рычаг у рангоута сильно больше, чем у киля: мачта далеко от оси вращения, и её
масса входит в момент инерции с квадратом плеча. Если период разойдётся с
памятью — искать надо в весовой сводке, а не в обводах.

## Симулятор

`sim/` — отдельное приложение, тоже на three.js и тоже одним самодостаточным
файлом. Физика идёт фиксированным шагом 1/30 с и не зависит от частоты кадров;
отрисовка интерполирует между шагами.

Четыре степени свободы: продольное движение, дрейф, рыскание, крен. Всплытие и
дифферент — квазистатически по таблице гидростатики: на тридцати герцах их
собственные колебания всё равно не разрешить, а на управление они влияют слабо.

Что откуда:

- **из геометрии** — массы, все три момента инерции, диаграмма GZ до 90°,
  гидростатика по осадке, площади, размахи и удлинения киля и руля,
  положение оси баллера и линии четверти хорды киля;
- **модели в коде симулятора** — коэффициенты парусов и крыльев (крыло со
  срывом, плавный переход к режиму плоской пластины), демпфирование;
- **подобрано** — кривая остаточного сопротивления. Для лёгкого глиссирующего
  корпуса надёжной серии нет, а Delft за своими пределами врёт, поэтому кривая
  калибрована под ожидаемую скорость и лежит отдельной таблицей
  (`RESIDUARY` в `scripts/build_physics.py`).

Управление: `←→` руль, `↑↓` шкот, `R` сброс; ветер, откренивание и парусность —
ползунками.

Физика проверяется **без браузера**:

```bash
make test        # node tests/physics.test.mjs
```

Тест гоняет модель на семи курсах под авторулевым, разворачивает лодку и
отпускает её из крена, а потом проверяет конкретные утверждения, а не «похоже
на правду». Ключевая из них — период свободной качки: он должен совпасть с тем,
что независимо посчитан по геометрии в пакете. Совпадает с точностью 1.3%.

| TWA | шкот | узлы | крен | дрейф | AWA | VMG |
|---:|---:|---:|---:|---:|---:|---:|
| 40° | 12° | 5.67 | 20.7° | −8.0° | 28° | 4.04 |
| 50° | 14° | 6.60 | 24.0° | −6.7° | 33° | 3.89 |
| 90° | 24° | 8.35 | 13.8° | −2.8° | 55° | −0.24 |
| 150° | 60° | 5.27 | 1.3° | −0.8° | 131° | −4.59 |

Разворот при руле 15°: радиус 6.5 длины корпуса, скорость падает с 8.3 до
3.7 узла.

Скорости здесь — не расчёт, а следствие подобранной кривой `RESIDUARY`;
она откалибрована по оценке владельца лодки, и в тестах на неё стоит отдельная
проверка, чтобы правка кривой не проехала мимо этой оценки незамеченной.

## Диаграмма остойчивости

GZ считается поворотом корпуса и отсечением замкнутого контура шпангоута
горизонтальной плоскостью; контур замыкается настоящей палубой, поэтому уход
кромки борта под воду учитывается сам собой.

| | |
|---|---:|
| Максимум GZ | 663 мм на 50° |
| Закат диаграммы | за 90° |
| Площадь до 30° | 0.197 м·рад |
| Сверка с GM на 2° | −0.8% |

Последняя строка — независимая проверка: GZ на малом угле обязан совпасть с
GM·sinθ, а GM пришла совсем другим путём, через момент инерции площади
ватерлинии. Сошлось.

Оговорка: палуба считается водонепроницаемой, заливание кокпита не
моделируется, поэтому за семьюдесятью градусами кривая оптимистична.

## Оговорка про версию лодки

Чертёж — проект 2010 года. Серийная SV20 с 2017 года по данным магазина
«Силы ветра» имеет 590 кг, осадку 1.55 м и парусность 25/56 м² против
550 кг / 1.60 м / 23 м² у проекта. Обводы строятся по чертежу проекта,
а гидростатика сводится к серийной лодке — той, поведение которой можно
проверить на воде. Цель задаётся в `calibrate.TARGET`.

## Структура

```
data/raw/610.pdf        исходный чертёж общего вида
src/sv20/pdf_paths.py   Ф0: разбор content stream PDF -> полилинии
src/sv20/calibrate.py   Ф0: привязка (ДП, КВЛ, оконечности, масштаб) + проверки
src/sv20/layers.py      Ф0: раскладка путей по видам чертежа
src/sv20/frame.py       Ф1: каркас, метрики, список пробелов
src/sv20/curves.py      Ф2: сплайны для продольных законов
src/sv20/sections.py    Ф2: шпангоут — днище, скула, борт
src/sv20/hullmodel.py   Ф2: параметры + границы -> шпангоуты и сетка
src/sv20/hydro.py       Ф2: гидростатика по шпангоутам
```
