# Подробные расчёты воздуха и воды

`cfd/cfd.py` — единая точка входа. Расчёты выполняются отдельно от симулятора;
подготовка, сбор результатов и инфраструктурные проверки работают без решателя.

- [Устройство, требования к результатам и приёмка](../docs/subsystems/offline-cfd.md).
- [Команды подготовки и запуска](../docs/guides/simulation.md).
- [Результаты и ограничения выполненных расчётов](../docs/research/cfd.md).
- [Следующие шаги](../docs/roadmap/next-steps.md).

## Каталоги

| Путь | Содержание |
|---|---|
| `lib/` | Манифесты, геометрия, шаблоны, запуск, сбор сил, сходимость и отчёты |
| `bridge/` | Запросы к той же модели, которая движет лодку в симуляторе |
| `templates/` | Шаблоны OpenFOAM; наследование через `_extends`, подстановка `{{имя}}` |
| `cases/` | Версионированные постановки расчётов |
| `images/` | Dockerfile решателя |
| [geometry](geometry/README.md) | Правила подготовки тел и сечений |
| [golden](golden/README.md) | Правила принятия компактных эталонов |
| [reports](reports/README.md) | Сравнения с интерактивной моделью |
| `../out/cfd/` | Производные сетки, поля и каталоги запуска; не коммитятся |

## Проверка без решателя

```sh
make t-cfd
.venv/bin/python cfd/cfd.py validate
.venv/bin/python cfd/cfd.py --help
```

`t-cfd` проверяет манифесты, координаты, геометрию, разворачивание шаблонов,
разбор сил, сходимость и отчёты на искусственных данных. Мост к симулятору
проверяется при наличии Node.js и `out/export/physics.json`; иначе сообщается пропуск.
Эта проверка входит в `make test` и не запускает OpenFOAM. На 2026-09-30
она имеет 20 существующих отказов группировки исследовательских серий;
[условия и результаты](../docs/research/cfd.md#состояние-проверки-инфраструктуры).

## Среда запуска

`lib/runners.py` обнаруживает нативный `openfoam2306` или Docker;
выбор можно задать через `CFD_RUNTIME`. Доступны локальный запуск, SSH и Slurm.
Наличие нужного решателя проверяется на конкретной машине, а не предполагается
по старому журналу. Версия и отпечаток сборки обязательны в манифесте и для
нативного запуска. Поле `solver.image` сохраняет идентичность программы.

Тяжёлые случаи запускаются последовательно и по отдельно согласованной постановке.
Изменение результата требует нового случая, а не ручной правки сохранённого каталога.
После подготовки `case.json` хранит отпечатки файлов; `collect` проверяет их.
Отчёт и статус расчёта сами по себе не разрешают замену физики симулятора.
