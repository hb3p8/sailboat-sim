# Разработка

## Подготовка

Нужны Python 3 и Node.js с поддержкой ES-модулей. Просмотр сцены требует браузер
с WebGPU. Разбор чертежа, базовая геометрия и экспорт используют стандартную
библиотеку Python; подгонка, подготовка акватории и часть тестов используют `.venv`.

```sh
python3 -m venv .venv
.venv/bin/pip install numpy scipy pillow
make fit
```

`make fit` получает `out/params.json` и затем строит основные результаты.
Этот файл нужен `scripts/build_physics.py` и не хранится в git. `make clean`
удаляет его вместе с производными данными; после этого потребуется новая подгонка.
Не запускайте подгонку на каждой итерации, если геометрия не менялась.

## Сборка

| Команда | Результат и область |
|---|---|
| `make` | Просмотрщик корпуса, экспорт и симулятор из подготовленных параметров |
| `make extract` | Разбор чертежа, каркас и измерения |
| `make hull` | Геометрия корпуса |
| `make physics` | `out/export/physics.json` и `sim_mesh.json` |
| `make sim` | Самодостаточная страница `sim/index.html` |
| `make terrain terrain-pack terrain-glb` | Акватория, физический пакет и графический ассет; нужен доступ к сети |
| `make kernel` | Вычислительные WASM-модули и JS-оболочка; нужен отдельный LLVM/lld |

`make serve` зависит от акватории; для обычного запуска без неё используйте
`python3 scripts/serve.py --port 8020 --no-open`. Сборка без акватории обязана работать.
Пересборка `sim/` нужна после изменения его JS, затем перезагрузите браузер.

Исходники фигурок экипажа и HDR-неба не входят в репозиторий. `make crew` и
`make sky` нужны только для изменения этих ассетов, а не для обычной сборки.
[Зависимости просмотрщика](../../viewer/vendor/README.md) поставляются в git.

## Границы кода

- `src/sv20/` и `scripts/build_physics.py` производят геометрию, массы и таблицы.
- `sim/physics.js` хранит состояние и объединяет силы. `aero.js`, `hydro.js`,
  `buoyancy.js`, `wind.js`, `waves.js` отвечают за свои физические области.
- `cloth.js`, `membrane.js`, `vlm.js`, `wake.js` описаны в [парусах](../subsystems/sails.md).
- `main.js` строит сцену; `controls.js` и `mobile.js` подают команды модели.
- `trace.js` задаёт общий формат записи для браузера, воспроизведения и проверок.
- `cfd/` считает отдельные подробные задачи; его данные проходят приёмку до
  переноса в интерактивную модель.

Сборщик вклеивает модули в один HTML и снимает импорты. Проверьте порядок
в `MODULES` файла `scripts/build_sim.py` и соответствующую метку
`/*__ИМЯ-МОДУЛЯ__*/` в `sim/template.html`, когда добавляете модуль:
успешный импорт в Node.js не означает его присутствие в браузере.

## Рабочий цикл

1. Выберите пользовательский результат и измеряемый признак его изменения.
2. Проверьте состояние соответствующей задачи и прежние отрицательные опыты.
3. Зафиксируйте условия исходного прогона, режим и пороги до изменения.
4. Меняйте одну причину за этап. Для чистого переноса кода сохраните отпечаток
   `node scripts/golden.mjs` до и после и требуйте побайтового совпадения.
5. Запустите относящиеся проверки по [руководству тестирования](testing.md).
6. Для сцены и управления проверьте собранную страницу, ошибки консоли и
   требуемый экран. Для производительности нужны измерения на целевом устройстве.
7. Обновите документацию и коммитьте законченный этап с результатом проверки.

При изменении координат пользуйтесь [единым контрактом](../reference/coordinates.md).
При изменении физики проверяйте связанные силы, моменты, форму и оба направления
ветра; полезный видимый эффект не позволяет принять ухудшение других частей модели.
