# Запуск и симуляция

## Браузер

Из корня репозитория после подготовки параметров:

```sh
make sim
python3 scripts/serve.py --port 8020 --no-open
```

- `/sim/index.html` — обычный экран.
- `/sim/index.html?ui=game` — игровой экран с основными органами управления.
- `/sim/index.html?ui=debug` — панель условий и исследовательских режимов.
- `/viewer/index.html` — геометрия корпуса, если выполнен `make viewer`.
- `/viewer/terrain.html` — карта и разметка, если выполнен `make terrain`.

После изменения исходников выполните `make sim` и перезагрузите страницу.
Открытие HTML с диска ограничивает загрузку ассетов, отправку профиля и запись
на сервер; для полной сцены предпочтителен сервер.

## Управление

| Орган | Действие |
|---|---|
| `←/→`, `A/D` | Руль; ручная команда отключает авторулевого |
| `↑/↓`, `W/S` | Подтянуть/отпустить основной парус |
| `R/F` | Подтянуть/отпустить стаксель |
| `N` | Поднять/убрать генакер; при подъёме стаксель убирается |
| `H` | Включить/выключить удержание курса |
| `C` | Камера |
| `X` | Начальное состояние |
| `?` или `/` | Подсказки |
| `G` | Переключить исследовательский вид |
| `P` | Записать снимок состояния и последних команд |

Положение экипажа меняется отдельно и сохраняется при смене стороны ветра.
Верёвка генакера задаётся длиной на панели; клавиши основных парусов её не
заменяют. Игровой экран содержит грот, стаксель, руль и посадку экипажа;
отдельного органа генакера в нём нет.

В панели по умолчанию включено опытное местное давление генакера (32 панели).
Для основного расчёта снимите галочку. Записывайте её состояние вместе с
условиями: одинаковая длина верёвки не делает два режима одинаковыми.

## Телефон и локальная сеть

```sh
python3 scripts/serve.py --port 8020 --no-open --lan
```

`--lan` автоматически включает TLS: WebGPU требует защищённого контекста.
Сервер печатает HTTPS-адрес и создаёт локальный сертификат в `out/dev-cert/`.
Браузер может потребовать действия пользователя для доверия сертификату.
Запись `data/marks.json` через сеть отключена; производные записи профиля и
снимков остаются в `out/`. Сервер раздаёт корень репозитория, поэтому используйте
доверенную сеть. `?ui=debug` на телефоне также меняет выбор мобильного качества:
не используйте его для замера обычного игрового режима.

## Снимок и воспроизведение

При работе через сервер кнопка снимка или `P` сохраняет JSON в `out/dumps/`
и показывает короткое имя. Без сервера скачивается файл. В браузере можно
перетащить JSON в окно; программные точки входа описаны в [записи](../subsystems/recording.md).

```sh
node scripts/replay.mjs a3f9c2
node scripts/replay.mjs out/dumps/20260930-a3f9c2.json --after 60
```

Имя и путь в примере замените своим снимком. Проверяйте отметку сборки и
поддержку опытного режима форматом записи: не объявляйте его воспроизводимым
только потому, что файл удалось открыть.

## Контрольные прогоны генакера без браузера

```sh
node tests/gennaker-trim-sequence.mjs 140 8.5 9 8.5
node tests/gennaker-trim-sequence.mjs 140 8.5 9 8.5 --local-pressure
node tests/gennaker-trim-sequence.mjs 150 8.5 9.2 9
node tests/gennaker-trim-map.mjs
node tests/gennaker-pressure-audit.mjs --mirror --gate
```

Прогоны выполняйте последовательно. Парный манёвр сравнивает изменяемую
настройку с неизменным контролем; печатает тягу, ход, геометрию и оценку
добавленной анимации отдельно. `--local-pressure` в парном тесте включает
16 панелей, тогда как браузерная галочка — 32. Зеркальный `--gate` у нынешнего
опытного режима известен как отрицательная проверка, а не обязательный успех.
Смотрите [текущее состояние](../project/status.md) и не называйте эти сценарии
подтверждённым учебным приёмом.

## Производительность

Добавьте `?noperf`, чтобы отключить отправку таймингов. Обычно сервер получает
профиль раз в секунду и сохраняет его в `out/perf/*.jsonl`:

```sh
python3 scripts/perf_report.py
python3 scripts/perf_report.py 20260930-ab12cd34.jsonl
```

Для сравнения отражений используйте `?bench=0`…`?bench=3`; для разбора цены
частей сцены — `?bench=0&benchparts`. Измеряйте одинаковые сборку, экран,
камеру, качество и условия. FPS и время подачи работы процессором не заменяют
измерение времени выполнения на видеокарте.

## Измерение исследовательской ткани в браузере

После `make cloth-solver` и подготовки завершённых коротких записей
`kkt-wasm` на 11×9 с обеих сторон (условия — в
[исследовании стоимости](../research/cloth-performance.md)):

```sh
node scripts/cloth_browser_fixture.mjs out/acceptance/implicit-full-scene-plus.json out/acceptance/cloth-sparse-20261002-simd.wasm out/acceptance/browser-cloth-v2-plus.json
node scripts/cloth_browser_fixture.mjs out/acceptance/implicit-full-scene-minus.json out/acceptance/cloth-sparse-20261002-simd.wasm out/acceptance/browser-cloth-v2-minus.json
python3 scripts/serve.py --port 8020 --no-open
```

Для полной сцены соберите `python3 scripts/build_sim.py` из чистого коммита,
сохраните отдельную копию `sim/index.html` в `out/acceptance/` и передайте
её путь четвёртым аргументом `cloth_browser_fixture.mjs`. Вход требует ту же
ревизию и хэш сборки, сохраняет хэши внешних ассетов. Откройте
`/sim/index.html?bench=0&cloth-review&series=имя`. Камера и лодка неподвижны;
одновременно работают обычная сцена воды/яхты и тот же Worker ткани.
CPU кадра и интервалы снимаются из основного цикла сцены. `scene.frames`
содержит реальные кадры и номера показанных шагов;
`scene.presentation.maxVisibleResultDelayMs` — максимальный возраст
показанной формы по часам перехода. Это отличается от возраста уже
полученного ответа `scheduler.maxResultDelayMs`. Последний контрольный шаг
должен попасть в кадр. Менять экран/условия во время замера нельзя;
изменение состава сцены или её размеров отклоняется. Этот режим не считает
движение лодки или новый воздух и не принимает интерактивный манёвр.

Откройте `/sim/cloth-browser-review.html?series=browser-cloth-v2`, выберите сторону и нажмите
«Измерить». Подготовьте вход из чистого коммита: иначе результат помечается
недействительным. Новые файлы создаются без перезаписи; для другой серии
используйте новый префикс `имя-plus/minus.json` и `?series=имя`.
Изменение исходника после подготовки отклоняется по SHA256.
Окно берётся из сохранённой постановки: 40 шагов посадки и
`60 × длительность в секундах` рабочих шагов при h=1/60 с.
Для 1 с проверяются 100 шагов, для 5 с — 340. Вход хранит явные
`measurement.warmupSteps/liveSteps/durationS`; браузер и валидатор требуют
согласования окна, числа контрольных шагов и модельного времени.
Границы воспроизведения — 10⁻⁸ м и 10⁻⁷ Дж, физические допуски неизменны.
Начальная загрузка и графические программы измеряются отдельно.
Выбор «Где считать» сравнивает основной поток с Worker. Переключатель
повторного использования памяти даёт контроль того же WASM без запаса.
В Worker изображение работает независимо и читает последний полученный
снимок; очередь запросов не накапливается. Задержка ответа и отставание
последнего результата записываются отдельно от интервалов изображения.
Рабочий цикл сохраняет накопленное время, делает до четырёх шагов за кадр
и записывает отставание; время не отбрасывается. Смена видимости во время
расчёта делает замер недействительным. Вывод и скачиваемый JSON содержат
среднее, медиану, 95-й процентиль и максимум, размер экрана и среду.
Это сцена одного паруса и пола, без моря, лодки и обратной связи воздуха.
Время подачи отрисовки CPU не означает время завершения GPU.
Проверка сохранённого результата по исходному коммиту, модулю, входу,
допускам и индивидуальным временам шагов:

```sh
node scripts/cloth_browser_report.mjs out/acceptance/browser-cloth-summary.json out/acceptance/browser-cloth-result-plus.json out/acceptance/browser-cloth-result-minus.json
```

Пути результатов замените на скачанные JSON. Выход создаётся без перезаписи.
`valid` означает корректное происхождение и повторение модели; это не
положительное заключение о скорости. Полная сцена отдельно измеряется
обычным `?bench=0`, а её лента сохраняется в `out/perf/`.

## Заданное движение угла под сохранённой нагрузкой

Для отдельной проверки механики используйте чистый сохранённый вход
`browser-full-five-before-plus/minus.json`. Его 40 шагов посадки проверяются
точно против прежних координат/энергии, затем задаётся ход угла в направлении
нижнего переднего крепления. Лодка и поле не пересчитываются; масса,
материал, верхняя планка и допуски прежние. Это не закон верёвки или замер
отклика браузера. Новый путь результата обязателен; перезапись отклоняется.

```sh
node tests/cloth-support-balance.test.mjs
node scripts/cloth_support_fixture.mjs out/acceptance/browser-full-five-before-plus.json 0.05 out/acceptance/supports-plus-60.json 60
node scripts/cloth_support_fixture.mjs out/acceptance/browser-full-five-before-plus.json 0.05 out/acceptance/supports-plus-120.json 120
node scripts/cloth_support_fixture.mjs out/acceptance/browser-full-five-before-plus.json 0.05 out/acceptance/supports-plus-240.json 240
node scripts/cloth_support_refinement.mjs out/acceptance/supports-plus-60.json out/acceptance/supports-plus-120.json out/acceptance/supports-plus-240.json out/acceptance/supports-plus-refinement.json
```

Повторите последовательно для `minus`, хода `−0.05` и нулевого хода.
Нулевой ход при 60 Гц дополнительно сравнивается точно с прежними 120
рабочими шагами. Переход — `sin⁴(πt/T)`, T=1 с, затем удержание 1 с;
скорость и ускорение на концах нулевые. Необязательный пятый аргумент
`sin2` сохраняет контроль со скачком ускорения. Команды/силы/позиции и
остатки общего баланса сохраняются на каждом шаге. Отказ тоже сохраняется
в отдельный JSON и завершает команду с ненулевым кодом.
Сравнение требует чистые физические записи и проверяет исходники по коммиту;
времена совпадают без интерполяции. История движения и накопленные работа/импульс реакции
измеряются целиком, итоговая работа записывается отдельно.

Для разбора резкого натяжения повторите сохранённый опыт
`node scripts/cloth_support_events.mjs движение.json новые-события.json`.
Инструмент проверяет текущую модель и записанный коммит, требует точного
повторения всех координат/реакций/энергий и сохраняет натяжение, импульс
и скорость раздвижения концов каждой жёсткой кромки. Пиковая сила идеально
нерастяжимого участка сама по себе не доказывает численную неустойчивость;
её ограниченность и перенос нагрузки лодке проверяются отдельно.
[Известный контроль и отрицательный полный случай](../research/cloth-material.md#резкое-натяжение-нижнего-края-отрицательный-контроль-пиковой-силы).

## Объединение подшагов нагрузки

Для проверки передачи реакций без нового расчёта ткани:

```sh
node scripts/cloth_support_impulses.mjs out/acceptance/новые-импульсы.json out/acceptance/cloth-supports-cf42ad9-sin4-{held,inward,outward}-{plus,minus}-{60,120,240}.json --boat-hz=30
```

`--boat-hz=60` даёт отдельную сводку для более короткого окна.
Пакеты содержат импульс, три интеграла момента и соответствующие средние
силу/моменты. Крен, начало моментов и лодка неподвижны. В исходных записях
реакция относится к точкам в конце подшага; с ними же вычисляется момент.
Приёмка переноса не принимает пиковые силы или динамику лодки.

## Ответ известного тела на пакеты

После сводки интегралов можно проверить ответ назначенной массы 10 кг и
инерции `[20,30,40]` кг·м² на каждое окно. Оси и ЦТ заморожены;
положение тела и связанная работа живых креплений не интегрируются.

```sh
node tests/sail-load.test.mjs
node tests/cloth-support-body.test.mjs
node scripts/cloth_support_body.mjs out/acceptance/новый-ответ-тела.json out/acceptance/cloth-supports-impulses-3974877-boat30.json out/acceptance/cloth-supports-impulses-3974877-boat60.json
```

Инструмент отклоняет перезапись, проверяет происхождение и сравнивает
каждый ответ с прямым суммированием исходных реакций. Вес ткани и
присоединённый воздух публикуются отдельно. Результат не принимает движение
SV20 и не меняет рабочий физический пакет;
[границы](../research/cloth-material.md#известный-ответ-тела-и-выделение-нагрузки-парусов).

## Двусторонний расчёт опоры и ткани

Перед подключением движущейся лодки проверьте известную двустороннюю
поступательную связь, без браузера:

```sh
node tests/cloth-body-coupling.test.mjs --out=out/acceptance/новая-связь-js.json
node tests/cloth-body-coupling.test.mjs --linear-backend=kkt-wasm --wasm=out/acceptance/cloth-sparse-20261002-simd.wasm --legacy-input=out/acceptance/cloth-supports-cf42ad9-sin4-inward-plus-60.json --legacy-input=out/acceptance/cloth-supports-cf42ad9-sin4-outward-minus-60.json --out=out/acceptance/новая-связь-wasm.json
```

Выход создаётся без перезаписи и содержит исходники/ревизию/модуль,
назначенные условия, известные результаты и отрицательный контроль задержки.
Оси инерциальные, опора не вращается, направление удерживает внешняя
направляющая; это не режим `Boat` и не закон верёвки;
[границы](../research/cloth-material.md#двустороннее-поступательное-движение-известной-опоры).

Для совместной массы опоры и аффинной верхней планки выполните отдельную
проверку известных нагрузок, длины, времени и малого полотна:

```sh
node tests/cloth-body-board.test.mjs --out=out/acceptance/новая-планка-js.json
node tests/cloth-body-board.test.mjs --linear-backend=kkt-wasm --wasm=out/acceptance/cloth-sparse-20261002-simd.wasm --out=out/acceptance/новая-планка-wasm.json
```

Доступны также `--linear-backend=sparse-js` и `sparse-wasm`. Новый выход
содержит полную массу и отрицательный контроль диагонального упрощения.
Существующие файлы не перезаписываются. Опора по-прежнему не вращается;
[условия приёмки планки](../research/cloth-material.md#совместная-масса-опоры-и-верхней-планки).

Свободное вращение известной опоры проверяется отдельно, до полного паруса:

```sh
node tests/cloth-rigid-body-coupling.test.mjs --out=out/acceptance/новое-свободное-тело-js.json
node tests/cloth-rigid-body-coupling.test.mjs --linear-backend=kkt-wasm --wasm=out/acceptance/cloth-sparse-20261002-simd.wasm --out=out/acceptance/новое-свободное-тело-wasm.json
```

Поддерживаются также `sparse-js` и `sparse-wasm`. Запись фиксирует заданные
массы/инерции, известные ответы, уточнение h, малое полотно и отрицательный
контроль буквального сохранения углового импульса. Выход создаётся без
перезаписи. Этот расчёт не подключён к `Boat`;
[границы и численное торможение](../research/cloth-material.md#свободное-вращение-тела-и-общая-работа-с-тканью).

## Экранные команды исследовательской ткани

### Полный парус на свободной опоре

Из чистой ревизии подготовьте новую запись для каждой стороны:

```sh
node scripts/cloth_rigid_sail_fixture.mjs out/acceptance/cloth-supports-cf42ad9-sin4-held-plus-60.json out/acceptance/новая-свободная-опора-plus-60.json 60 1
node scripts/cloth_rigid_sail_fixture.mjs out/acceptance/cloth-supports-cf42ad9-sin4-held-minus-60.json out/acceptance/новая-свободная-опора-minus-five.json 60 5
node tests/cloth-rigid-sail-worker.test.mjs --input=out/acceptance/новая-свободная-опора-minus-five.json --out=out/acceptance/новая-сводка-worker.json
```

Повторите 1 с на 120/240 Гц и 5 с на 60 Гц для обеих сторон, последовательно.
Для уточнения передайте три записи одной стороны в порядке 60/120/240 Гц:

```sh
node scripts/cloth_rigid_sail_refinement.mjs out/acceptance/новое-уточнение.json out/acceptance/новая-свободная-опора-plus-60.json out/acceptance/новая-свободная-опора-plus-120.json out/acceptance/новая-свободная-опора-plus-240.json
node scripts/cloth_rigid_sail_review.mjs out/acceptance/новая-свободная-опора-plus-five.json out/acceptance/новая-свободная-опора-minus-five.json out/acceptance/свободная-опора-review.html
```

Все выходы создаются без перезаписи. Откройте созданный HTML через локальный
сервер и нажмите сторону. Стенд проверяет происхождение входа/исходников,
WASM и все физические поля против Node. Сохраните исходный текст полной
измеренной записи: преобразование промежуточного объекта инструментом
может округлить число. Три парных запуска после перезагрузки отделяют
подготовку/первую секунду от рабочего окна 1–5 с; все исходные длительности
и выбросы сохраняются. Это расчёт лабораторной опоры и ткани со старым
замороженным полем, не живой `Boat` или полный кадр симулятора.
[Постановка](../research/cloth-material.md#полный-парус-на-свободной-опоре),
[стоимость](../research/cloth-performance.md#worker-полного-паруса-со-свободной-опорой).

### Общий шаг с обобщённой инерцией воды

Сначала `node tests/cloth-fluid-body.test.mjs --out=out/acceptance/новый-контроль-воды.json`:
известные перенос/вращение/пружина/нить, общий материал/изгиб, работа/отказ,
зеркала и уточнение времени. Затем последовательный короткий полный контроль:

```sh
node scripts/cloth_fluid_sail_fixture.mjs out/acceptance/rigid-sail-60321b9-plus-five.json out/acceptance/новая-вода-plus.json 1
node scripts/cloth_fluid_sail_fixture.mjs out/acceptance/rigid-sail-60321b9-minus-five.json out/acceptance/новая-вода-minus.json 1
```

Третий аргумент — 1–1800 шагов по сохранённому h; по умолчанию один.
`--hz=60|120|240` явно задаёт уточнение времени. Используется чистая прежняя
серия 11×9 с лабораторным телом 1000 кг; её SHA проверяются по Git. Вода
задана отдельной назначенной матрицей энергии, её вес не добавляется.
Поле воздуха/веса/сопротивления ткани остаётся замороженным. Первый отказ
и принятые шаги сохраняются в новом JSON; прежний результат не перезаписывается.
Контрольный `reference-dense` остаётся по умолчанию; он медленный.
Блочное ускорение явно выбирается вместе с WASM. Сначала повторите малые
задачи в обоих методах, затем полные серии последовательно:

```sh
node tests/cloth-fluid-body.test.mjs --linear-backend=schur-wasm --wasm=out/acceptance/cloth-sparse-20261002-simd.wasm --out=out/acceptance/новый-блочный-контроль.json
node scripts/cloth_fluid_sail_fixture.mjs out/acceptance/rigid-sail-60321b9-plus-five.json out/acceptance/новая-вода-plus-60.json 60 --hz=60 --linear-backend=schur-wasm --wasm=out/acceptance/cloth-sparse-20261002-simd.wasm
node scripts/cloth_fluid_refinement.mjs out/acceptance/новое-уточнение-воды.json out/acceptance/новая-вода-plus-60.json out/acceptance/новая-вода-plus-120.json out/acceptance/новая-вода-plus-240.json
```

Для последней команды сначала подготовьте 120 и 240 шагов на 120/240 Гц
с теми же исходниками/входом и общей длительностью; повторите для другой стороны.
`--without-newton-control` относится к малой проверке: это отрицательный
вариант без завершающего корректора, ожидаются отказ и `phase=failed`.
Ускорение не является запуском интерактивной яхты.
[Уравнение, числа и границы](../research/boat-coupling.md#общий-шаг-обобщённой-инерции-и-ткани).

### Команды в основной исследовательской сцене

Из чистого коммита соберите сцену, сохраните новую копию `sim/index.html`
в `out/acceptance/` и подготовьте входы из полных опытов 60 Гц:

```sh
python3 scripts/build_sim.py
node scripts/cloth_support_browser_fixture.mjs out/acceptance/cloth-supports-cf42ad9-sin4-inward-plus-60.json out/acceptance/scene-new.html out/acceptance/browser-supports-plus-inward.json
```

`scene-new.html` — сохранённая копия текущей чистой сборки. Повторите
для `held/inward/outward` и `plus/minus`; новые пути обязательны.
Откройте `/sim/index.html?bench=0&cloth-review&support-commands&series=browser-supports`.
Выберите сторону и действие, нажмите «Подготовить». После посадки
нажмите кнопку движения. Загрузка и посадка исключены из задержки команды;
отдельно сохраняются времена до запроса, ответа и первого кадра с результатом.
Траектория задана, лодка и поле неподвижны. Это проверка передачи управления,
а не учебный манёвр или модель верёвки. Во время измерения сохраняйте
видимость, размер экрана и состав сцены. Скачанный JSON проверяется тем же
`cloth_browser_report.mjs`; он сверяет каждую команду, ответ и показанный шаг.
При автоматическом сохранении читайте текст элемента `report` целиком
или используйте скачанный файл. Не передавайте разобранный объект через
посредника, округляющего числа: точная история координат команды должна
сохраниться. Отдельная проверка валидатора не считает ткань заново:

```sh
node tests/cloth-browser-command-report.test.mjs --input=out/acceptance/browser-supports-255fecd-plus-inward-3-raw.json
```

Действительные записи включают и медленные запуски. Сохраняйте их в общей
сводке; `valid:true` означает проверенные происхождение/повторение модели,
а не принятый темп или задержку управления.

Для раздельной стоимости стадий подготовьте отдельный вход с последним
аргументом `--profile-worker` и откройте его серию с `&worker-profile`.
Режим должен совпадать с входом. Время загрузки/проверки, подготовки Worker,
сцены, предварительных кадров и посадки сохраняется в `preparation.timeline`.
На каждом шаге `timing` разделяет разложение, решение правой части,
остальную работу шага и подготовку снимка. Это длительности оболочки,
включая копирование её входа/выхода, не чистое время инструкций WASM.
Время ожидания запроса в основном потоке и время сверки снимка сохраняются
отдельно. Часы Worker не сравниваются с абсолютными метками основного потока.
Замеры добавляют работу: нужна парная серия того же входа без `worker-profile`,
а не утверждение об ускорении по одному инструментированному запуску.

## Подробный расчёт воздуха и воды (CFD)

CFD выполняется вне интерактивного шага. Его запуск требует отдельного решения
по постановке и стоимости; документационная правка или подготовка сетки не
разрешает автоматически запускать решатель.

```sh
.venv/bin/python cfd/cfd.py validate
.venv/bin/python cfd/cfd.py geometry --canonical
.venv/bin/python cfd/cfd.py sail --section gen-c18,0.18,0.5
.venv/bin/python cfd/cfd.py case --case naca0012-a10-medium
```

Геометрия корпуса требует подготовленного экспорта (`make export`). Команда
`case` создаёт отдельный каталог; не используйте `--force` для сохранённого
результата. Для новой постановки заведите новый `case_id`.

После авторизации конкретного запуска:

```sh
.venv/bin/python cfd/cfd.py run --case naca0012-a10-medium --runner local
.venv/bin/python cfd/cfd.py collect --run out/cfd/runs/naca0012-a10-medium
.venv/bin/python cfd/cfd.py slices --run out/cfd/runs/naca0012-a10-medium
.venv/bin/python cfd/cfd.py convergence --family verification
.venv/bin/python cfd/cfd.py report --family verification
.venv/bin/python cfd/cfd.py html
```

Примеры идентификаторов не являются заданием повторить расчёт. Сначала проверьте
существующие результаты и манифесты. Runtime обнаруживается в `cfd/lib/runners.py`:
нативный `openfoam2306` или Docker; доступны также SSH/Slurm runners. Зафиксируйте
версию и отпечаток программы. Не устанавливайте решатель без необходимости.

Очередь предварительно просматривается `.venv/bin/python cfd/scripts/queue.py --dry`.
Запускайте случаи по одному. Критерии приёмки — в [описании CFD](../subsystems/offline-cfd.md),
актуальное состояние и ближайшие действия — в соответствующих реестрах проекта.

## Совместный опыт управления генакером

Общий [протокол приёмки](../reference/gennaker-acceptance.md) снимает ткань,
нагрузку до движения узлов, силы лодки и одновременный контроль. Основные
сценарии запускаются последовательно, отчёты сохраняются с отпечатками:

```sh
node tests/gennaker-acceptance.mjs --out=out/acceptance/baseline.json
node tests/gennaker-acceptance.mjs --case=core --local-pressure --panels=32 --out=out/acceptance/core-local32.json
```

Для полного разбора формы добавьте `--trace` к отдельному случаю: файл содержит
положения узлов после шага и отдельный снимок узлов/нормалей/сил в момент нагрузки.
Размер такого файла существенно больше сводки. Непроверенные условия в JSON
остаются `null`; `--gate` завершает неполную физическую приёмку кодом 1.

## Живой лабораторный парус с обобщённой водой

`?bench=0&fluid-live=имя-серии` включает общую модель 11×9 в основной
WebGPU-сцене. Обычный `Boat` не шагает. Worker считает новые положения ткани
и опоры; изображение читает только принятый ответ, без дополнительной
анимации полотна. Сцена моря остаётся неподвижной, акватория скрыта.
Начало и масса опоры лабораторные; корпус служит ориентиром, его физический
пакет не заменяет назначенные массу/инерцию опыта.

Подготовьте новую серию из сохранённых входов на чистом дереве после сборки:

```sh
python3 scripts/build_sim.py
node scripts/cloth_fluid_live_fixture.mjs --input=out/acceptance/rigid-sail-60321b9-plus-five.json --input=out/acceptance/rigid-sail-60321b9-minus-five.json --sheet-input=out/acceptance/fluid-rope-sail-70381c0-plus-60.json --sheet-input=out/acceptance/fluid-rope-sail-70381c0-minus-60.json --out-prefix=out/acceptance/fluid-live-review --wasm=out/acceptance/cloth-sparse-20261002-simd.wasm
```

Откройте `http://127.0.0.1:8020/sim/index.html?bench=0&fluid-live=fluid-live-review`.
Имя серии должно состоять из латинских букв, цифр, `_` и `-`. Подготовщик не
перезаписывает старые входы и сохраняет отдельный снимок HTML для будущей
сверки записей. Перед запуском браузер проверяет SHA исходников,
сцены, пакета, WASM и опыта верёвки. Без двух `--sheet-input` подготовщик
сохраняет прежний режим с тремя закреплёнными углами. При изменении исходников пересоберите сцену и подготовьте
новую серию.

Выберите сторону при перезапуске, нажмите «Начать заново», затем «Запустить».
Можно менять масштаб сохранённого давления 0–150% и внешний момент
−100…100 Н·м, сделать один шаг, поставить расчёт на паузу и начать заново.
Изменение ползунка действует со следующего отправленного шага. Отказ
останавливает опыт на последнем принятом изображении, без скрытого сброса
или ослабления допусков. Один запуск ограничен 300 шагами (5 с при 60 Гц).
Пауза допускает завершение уже отправленного шага; очереди догоняющих
шагов нет. На медленном устройстве модельное время отстаёт.

«Отпускать», «Подтягивать», «Держать» задают команду следующего шага,
её можно выбрать и перед запуском. Скорость изменения — 0.5 м/с времени
модели; диапазон — начальная длина +25 см. На границах длина удерживается.
Это проверенное окно стенда, не пределы настоящего управления SV20.
Пауза возвращает ручную команду на «Держать». Показания длины, натяжения
и провиса относятся к последнему принятому шагу.

«Показать цикл» начинает опыт заново с нагрузкой 100% и моментом 0 Н·м,
с выбранной стороны: держать 0.5 с, отпустить 25 см за 0.5 с, держать
0.5 с, вернуть за 0.5 с, держать до 3 с. Затем расчёт останавливается.
Ручная команда выводит из автоматического цикла. Для повторения нажмите
«Показать цикл» снова. Сторона меняется при новом запуске.

«Нагрузка» не является скоростью ветра: меняется только давление заданного
неподвижного поля, вес и сопротивление ткани сохраняются. Внешний момент
не является рулём. Нет нового закона воздуха, плавучести или
сопротивления движущегося корпуса. Это возможность живого исследования,
не принятый учебный сценарий G1–G4/C1. Пик натяжения идеальной
нерастяжимой верёвки зависит от шага при выборе провиса и пока не принят
как реальная нагрузка.

«Скачать запись» доступно после паузы и завершения отправленного шага;
сохраняет вход/происхождение, все команды, положения,
скорости опоры, силы и аудит. Каждый шаг можно независимо повторить:

```sh
node scripts/cloth_fluid_live_report.mjs путь-к-записи.json новый-отчёт.json
node tests/cloth-fluid-worker.test.mjs --input=out/acceptance/rigid-sail-60321b9-plus-five.json --input=out/acceptance/rigid-sail-60321b9-minus-five.json --expected=out/acceptance/fluid-state-five-6e4f505-plus-60.json --expected=out/acceptance/fluid-state-five-6e4f505-minus-60.json --wasm=out/acceptance/cloth-sparse-20261002-simd.wasm
```

Проверка записи требует сохранённых файлов и соответствующих исходников.
`valid:true` означает точное повторение, а не принятие бюджета или сходства
с настоящей яхтой. Темп на панели учитывает расчёт/доставку ответа, исключает
паузы и ожидание следующего шага; он не является частотой отрисовки.

Текущий подготовленный вход:
`http://127.0.0.1:8020/sim/index.html?bench=0&fluid-live=fluid-live-rope-dbffdcb`.
Для быстрого просмотра нажмите «Начать заново», затем «Показать цикл»;
повторите с другой стороной. Оба чистых цикла и ручные команды проверены
точным Node-повтором; [условия и стоимость](../research/boat-coupling.md#верёвка-в-живом-экране).
Исходная сцена собирается явной командой выше: изменения исследовательских
`.mjs` и метаданных Git могут не вызвать пересборку через `make sim`.
Ленточки штатного `Rig` скрыты в лабораторном режиме: живой воздух и его
показания для движущейся ткани ещё не получены.

### Сравнение излома и плотности сетки

[Сохранённые кадры трёх сеток](http://127.0.0.1:8020/out/acceptance/fluid-mesh-b9f7801-review.html)
показывают тот же аналитический крой при уплотнении высоты и ширины.
Выберите сторону, 100/150% давления и время; вращение мышью и масштаб
колесом общие для всех карточек. «Показать сетку» включает только линии
треугольников. Форма читается из расчёта без сглаживания или интерполяции.
При 2/5 с карточка 41×33 пустая: её опыт закончен на 1 с, следующий кадр
не подставляется. Это сравнение сохранённых состояний, не замер живой
скорости или приёмка гладкости у углов;
[команды и результаты](../research/boat-coupling.md#излом-при-усилении-нагрузки).
