# Запуск и симуляция

## Браузер

Из корня репозитория после подготовки параметров:

```sh
make sim
python3 scripts/serve.py --port 8020 --no-open
```

- `/sim/index.html` — обычный экран.
- `/sim/index.html?ui=game` — игровой экран с основными органами управления.
- `/sim/index.html?ui=debug` — панель условий и исследовательских режимов.
- `/viewer/index.html` — геометрия корпуса, если выполнен `make viewer`.
- `/viewer/terrain.html` — карта и разметка, если выполнен `make terrain`.

После изменения исходников выполните `make sim` и перезагрузите страницу.
Открытие HTML с диска ограничивает загрузку ассетов, отправку профиля и запись
на сервер; для полной сцены предпочтителен сервер.

## Управление

| Орган | Действие |
|---|---|
| `←/→`, `A/D` | Руль; ручная команда отключает авторулевого |
| `↑/↓`, `W/S` | Подтянуть/отпустить основной парус |
| `R/F` | Подтянуть/отпустить стаксель |
| `N` | Поднять/убрать генакер; при подъёме стаксель убирается |
| `H` | Включить/выключить удержание курса |
| `C` | Камера |
| `X` | Начальное состояние |
| `?` или `/` | Подсказки |
| `G` | Переключить исследовательский вид |
| `P` | Записать снимок состояния и последних команд |

Положение экипажа меняется отдельно и сохраняется при смене стороны ветра.
Верёвка генакера задаётся длиной на панели; клавиши основных парусов её не
заменяют. Игровой экран содержит грот, стаксель, руль и посадку экипажа;
отдельного органа генакера в нём нет.

В панели по умолчанию включено опытное местное давление генакера (32 панели).
Для основного расчёта снимите галочку. Записывайте её состояние вместе с
условиями: одинаковая длина верёвки не делает два режима одинаковыми.

## Телефон и локальная сеть

```sh
python3 scripts/serve.py --port 8020 --no-open --lan
```

`--lan` автоматически включает TLS: WebGPU требует защищённого контекста.
Сервер печатает HTTPS-адрес и создаёт локальный сертификат в `out/dev-cert/`.
Браузер может потребовать действия пользователя для доверия сертификату.
Запись `data/marks.json` через сеть отключена; производные записи профиля и
снимков остаются в `out/`. Сервер раздаёт корень репозитория, поэтому используйте
доверенную сеть. `?ui=debug` на телефоне также меняет выбор мобильного качества:
не используйте его для замера обычного игрового режима.

## Снимок и воспроизведение

При работе через сервер кнопка снимка или `P` сохраняет JSON в `out/dumps/`
и показывает короткое имя. Без сервера скачивается файл. В браузере можно
перетащить JSON в окно; программные точки входа описаны в [записи](../subsystems/recording.md).

```sh
node scripts/replay.mjs a3f9c2
node scripts/replay.mjs out/dumps/20260930-a3f9c2.json --after 60
```

Имя и путь в примере замените своим снимком. Проверяйте отметку сборки и
поддержку опытного режима форматом записи: не объявляйте его воспроизводимым
только потому, что файл удалось открыть.

## Контрольные прогоны генакера без браузера

```sh
node tests/gennaker-trim-sequence.mjs 140 8.5 9 8.5
node tests/gennaker-trim-sequence.mjs 140 8.5 9 8.5 --local-pressure
node tests/gennaker-trim-sequence.mjs 150 8.5 9.2 9
node tests/gennaker-trim-map.mjs
node tests/gennaker-pressure-audit.mjs --mirror --gate
```

Прогоны выполняйте последовательно. Парный манёвр сравнивает изменяемую
настройку с неизменным контролем; печатает тягу, ход, геометрию и оценку
добавленной анимации отдельно. `--local-pressure` в парном тесте включает
16 панелей, тогда как браузерная галочка — 32. Зеркальный `--gate` у нынешнего
опытного режима известен как отрицательная проверка, а не обязательный успех.
Смотрите [текущее состояние](../project/status.md) и не называйте эти сценарии
подтверждённым учебным приёмом.

## Производительность

Добавьте `?noperf`, чтобы отключить отправку таймингов. Обычно сервер получает
профиль раз в секунду и сохраняет его в `out/perf/*.jsonl`:

```sh
python3 scripts/perf_report.py
python3 scripts/perf_report.py 20260930-ab12cd34.jsonl
```

Для сравнения отражений используйте `?bench=0`…`?bench=3`; для разбора цены
частей сцены — `?bench=0&benchparts`. Измеряйте одинаковые сборку, экран,
камеру, качество и условия. FPS и время подачи работы процессором не заменяют
измерение времени выполнения на видеокарте.

## Измерение исследовательской ткани в браузере

После `make cloth-solver` и подготовки завершённых коротких записей
`kkt-wasm` на 11×9 с обеих сторон (условия — в
[исследовании стоимости](../research/cloth-performance.md)):

```sh
node scripts/cloth_browser_fixture.mjs out/acceptance/implicit-kkt-clean-small-plus.json out/acceptance/cloth-sparse-20261002-simd.wasm out/acceptance/browser-cloth-plus.json
node scripts/cloth_browser_fixture.mjs out/acceptance/implicit-kkt-clean-small-minus.json out/acceptance/cloth-sparse-20261002-simd.wasm out/acceptance/browser-cloth-minus.json
python3 scripts/serve.py --port 8020 --no-open
```

Откройте `/sim/cloth-browser-review.html`, выберите сторону и нажмите
«Измерить». Подготовьте вход из чистого коммита: иначе результат помечается
недействительным. Новые файлы создаются без перезаписи; для другой серии
используйте новый префикс `имя-plus/minus.json` и `?series=имя`.
Изменение исходника после подготовки отклоняется по SHA256.
Браузер проверяет все 100 шагов: 40 посадки и 60 при h=1/60 с.
Границы воспроизведения — 10⁻⁸ м и 10⁻⁷ Дж, физические допуски неизменны.
Начальная загрузка и графические программы измеряются отдельно.
Рабочий цикл сохраняет накопленное время, делает до четырёх шагов за кадр
и записывает отставание; время не отбрасывается. Смена видимости во время
расчёта делает замер недействительным. Вывод и скачиваемый JSON содержат
среднее, медиану, 95-й процентиль и максимум, размер экрана и среду.
Это сцена одного паруса и пола, без моря, лодки и обратной связи воздуха.
Время подачи отрисовки CPU не означает время завершения GPU.
Проверка сохранённого результата по исходному коммиту, модулю, входу,
допускам и индивидуальным временам шагов:

```sh
node scripts/cloth_browser_report.mjs out/acceptance/browser-cloth-summary.json out/acceptance/browser-cloth-result-plus.json out/acceptance/browser-cloth-result-minus.json
```

Пути результатов замените на скачанные JSON. Выход создаётся без перезаписи.
`valid` означает корректное происхождение и повторение модели; это не
положительное заключение о скорости. Полная сцена отдельно измеряется
обычным `?bench=0`, а её лента сохраняется в `out/perf/`.

## Подробный расчёт воздуха и воды (CFD)

CFD выполняется вне интерактивного шага. Его запуск требует отдельного решения
по постановке и стоимости; документационная правка или подготовка сетки не
разрешает автоматически запускать решатель.

```sh
.venv/bin/python cfd/cfd.py validate
.venv/bin/python cfd/cfd.py geometry --canonical
.venv/bin/python cfd/cfd.py sail --section gen-c18,0.18,0.5
.venv/bin/python cfd/cfd.py case --case naca0012-a10-medium
```

Геометрия корпуса требует подготовленного экспорта (`make export`). Команда
`case` создаёт отдельный каталог; не используйте `--force` для сохранённого
результата. Для новой постановки заведите новый `case_id`.

После авторизации конкретного запуска:

```sh
.venv/bin/python cfd/cfd.py run --case naca0012-a10-medium --runner local
.venv/bin/python cfd/cfd.py collect --run out/cfd/runs/naca0012-a10-medium
.venv/bin/python cfd/cfd.py slices --run out/cfd/runs/naca0012-a10-medium
.venv/bin/python cfd/cfd.py convergence --family verification
.venv/bin/python cfd/cfd.py report --family verification
.venv/bin/python cfd/cfd.py html
```

Примеры идентификаторов не являются заданием повторить расчёт. Сначала проверьте
существующие результаты и манифесты. Runtime обнаруживается в `cfd/lib/runners.py`:
нативный `openfoam2306` или Docker; доступны также SSH/Slurm runners. Зафиксируйте
версию и отпечаток программы. Не устанавливайте решатель без необходимости.

Очередь предварительно просматривается `.venv/bin/python cfd/scripts/queue.py --dry`.
Запускайте случаи по одному. Критерии приёмки — в [описании CFD](../subsystems/offline-cfd.md),
актуальное состояние и ближайшие действия — в соответствующих реестрах проекта.

## Совместный опыт управления генакером

Общий [протокол приёмки](../reference/gennaker-acceptance.md) снимает ткань,
нагрузку до движения узлов, силы лодки и одновременный контроль. Основные
сценарии запускаются последовательно, отчёты сохраняются с отпечатками:

```sh
node tests/gennaker-acceptance.mjs --out=out/acceptance/baseline.json
node tests/gennaker-acceptance.mjs --case=core --local-pressure --panels=32 --out=out/acceptance/core-local32.json
```

Для полного разбора формы добавьте `--trace` к отдельному случаю: файл содержит
положения узлов после шага и отдельный снимок узлов/нормалей/сил в момент нагрузки.
Размер такого файла существенно больше сводки. Непроверенные условия в JSON
остаются `null`; `--gate` завершает неполную физическую приёмку кодом 1.
