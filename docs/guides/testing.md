# Тестирование

## Выбор объёма

На итерациях и перед коммитом запускаются относящиеся к правке проверки в
регрессионном режиме. Полный набор дорог; выбор сокращается по затронутому
поведению, а не по желаемому цвету отчёта.

Полный режим (`--full` или `SV20_FULL=1`) нужен при провале регрессии, изменении
отпечатка или риске за пределами проверенной области. Реализация режимов —
`tests/lib/mode.mjs`; режим влияет на густоту сценариев и длительность там,
где он используется, но не отменяет критерии проверки. Передайте `--full`
отдельному тесту; `make test --full` не является командой этого режима.

## Наборы Makefile

| Команда | Состав и смысл |
|---|---|
| `make test` | Сборка пакета, Python-проверки section/bl/panel/milgram/polar/cfd и FAST-проверки JS |
| `make slow` | coupled, upwind, wake, wing |
| `make all-tests` | `test` + `slow`; не включает эталонные `ref` |
| `make ref` | sailforce, upwindforce: сравнение с внешними измерениями |
| `make t-axes` | Пример отдельной Make-проверки |
| `make docs-check` | Локальные ссылки, разделы и доступность документации; без сборки |
| `node tests/gennaker-observables.test.mjs` | Независимая проверка общих измерителей формы/нагрузки |
| `node tests/gennaker-acceptance.mjs` | Совместный диагностический протокол; `--gate` требует полную приёмку |
| `node tests/gennaker.test.mjs` | Генакер отдельно; не входит в FAST/SLOW |
| `node tests/planing.test.mjs` | Глиссирование отдельно; не входит в FAST/SLOW |

FAST: `axes buoyancy membrane cloth vlm waves ocean wind terrain replay physics
sailcoeffs kernel`. Python-проверки требуют `.venv` с нужными библиотеками.
Makefile — источник состава наборов: обновляйте эту таблицу при его изменении.
Не используйте `make -j` для тяжёлых исследований и CFD.

## Что проверять при изменении подсистемы

| Изменение | Начальный выбор; расширяется по затронутым связям |
|---|---|
| Координаты, знаки и экспорт | axes; cfd, геометрические проверки при затронутом пакете |
| Общая аэродинамика и таблица сил | wind, vlm, sailcoeffs, wake; силы sailforce/upwindforce при влиянии на них |
| Генакер и ткань | cloth, gennaker; парный манёвр, зеркальный аудит, карта и сходимость при соответствующей правке |
| Дальние ограничения ткани | `cloth-attachment-paths.test.mjs`; постоянная нагрузка на вложенных сетках и совместный протокол для явного варианта |
| Жёсткое верхнее крепление | `cloth-rigid-board.test.mjs`; работа/инерция/момент и вращение отдельной планки, затем постоянные силы на всём парусе и совместный протокол |
| Мягкие связи и работа ткани | `cloth-mechanics.test.mjs`; замороженный стенд с `--mechanics`, исключение одной семьи связей и запись фактического подшага |
| Энергия нового материала | `cloth-material.test.mjs`; `cloth-material-refinement.mjs --bending=curvature --gate`, затем полный крой/движение; `--bending=hinge` — сохранённый отрицательный контроль |
| Движение нового материала | `cloth-energy-motion.test.mjs`; затем `--energy-material` в замороженном стенде, контроль податливости, уравнения движения и физического силового остатка по отдельности |
| Подшаг и история скорости ткани | `cloth-time-step.test.mjs`, cloth и replay; обе стороны перехода времени, снимок, затем затронутые замороженный/совместный прогоны |
| Местное давление | local-pressure, local-pressure-coupling; замороженная форма, оба направления ветра и связанная ткань |
| Корпус, экипаж и плавучесть | buoyancy, physics; planing/stability при затронутом поведении |
| Ветер и волны | wind, waves, ocean; physics при изменении нагрузки лодки |
| Акватория | terrain; режим без пакета и затронутые силы лодки |
| Запись состояния | replay; новый орган управления должен быть проверен внутри записи |
| CFD-инфраструктура | `make t-cfd`, `cfd.py validate`; специальные геометрические проверки по задаче |
| Сцена и управление | `make sim`, браузер и консоль; целевое устройство при изменении удобства или скорости |
| Только документация | `make docs-check`, сверка команд/статуса и `git diff --check`; физические батареи не нужны |

Проверки запускаются напрямую, например:

```sh
node tests/cloth.test.mjs
node tests/gennaker.test.mjs
node tests/local-pressure.test.mjs
node tests/local-pressure-coupling.test.mjs
.venv/bin/python tests/cfd.test.py
```

## Разные виды результата

**Регрессия:** сохраняются заданные свойства модели. **Сопоставление с
измерением:** модель ограничена независимыми данными. **Диагностический
эксперимент:** локализована причина или записан отрицательный вариант.
Эти результаты не подменяют друг друга.

Состояние `t-cfd` на 2026-09-30: 20 существующих отказов группировки серий;
[условия и повтор исходной ревизии](../research/cfd.md#состояние-проверки-инфраструктуры).
Не считайте весь набор успешным по одному `validate`.

Красный `ref` означает расхождение с эталоном, которое нужно объяснить.
Диагностика может штатно печатать отрицательный результат; её код выхода и
пороги должны быть указаны в записи. Не добавляйте такой опыт в обязательную
зелёную батарею без принятого смысла проверки.

## Приёмка нового режима генакера

Сохраняются существующие ограничения `Γmax < 300` и шагового скачка общей тяги
`≤ 5 %` в проверках, которые их задают. В `gennaker.test.mjs` есть и другие
критерии, включая размах на установившемся режиме; они не тождественны шаговому
скачку. Не переносите один процент из одной проверки в другую.

Единый [контракт совместной приёмки](../reference/gennaker-acceptance.md)
задаёт станции, фазы нагрузки, окна, сценарии и формат результата.
`gennaker-observables.test.mjs` проверяет сами измерители; это не приёмка физики.
`gennaker-acceptance.mjs` запускается отдельно и не включён в FAST/SLOW.

Нужны оба направления ветра, несколько соседних режимов и начальных состояний,
парный манёвр 140°/6 м/с/8.5→9.0→8.5 м, глубокий курс 150°/8.5→9.2 м,
сходимость ткани и времени. Заворот измеряется по геометрии, а не по добавленной
анимации. Максимум скорости не обязан находиться внутри текущей шкалы верёвки.

Для чистого переноса кода:

```sh
node scripts/golden.mjs > /tmp/sv20-before.txt
# После правки:
node scripts/golden.mjs > /tmp/sv20-after.txt
diff -u /tmp/sv20-before.txt /tmp/sv20-after.txt
```

Отпечаток включает генакер. Сохраняйте одинаковый физический пакет и условия;
совпадение не доказывает достоверность, а только неизменность проверенных сценариев.

## Как записать проверку

Для изолированной механики генакера:

```sh
node tests/cloth-mechanics.test.mjs
node tests/cloth-frozen-aero-grid.mjs --tack=1 --sheet=9 --iter=40 --fixed-load --cols=17,33 --mechanics --edges --attachment-paths --rigid-board --out=out/acceptance/mechanics-full-plus.json
```

Контроли: отдельные `--without-shear`, `--without-bend`, затем оба флага;
другая сторона — `--tack=-1`. Уточнение — `--iter=160` и `--cloth-hz=120`.
Подшаг при 30/60 кадрах одинаков, поэтому проверять его нужно по JSON,
а не по частоте внешнего цикла. `--mechanics` отделяет посадку от длительности;
для прежнего отсчёта не передавайте этот флаг. `--seconds=1` пригоден для
короткой проверки инструмента, не для приёмки установившегося паруса.

Для нового заданного материала вместо прежнего проектора:

```sh
node tests/cloth-energy-motion.test.mjs
node tests/cloth-frozen-aero-grid.mjs --tack=1 --sheet=9 --iter=40 --fixed-load --cols=9,17,33 --mechanics --rigid-board --energy-material --hold-cut-clew --cut-nesting --seconds=30 --out=out/acceptance/energy-motion-full-plus.json
```

`--energy-material` требует неподвижных углов; прежние мягкие связи и дальние
пределы отключены. Энергия и остатки — в `energyMotion`; прежний наблюдатель
не получает выдуманных реакций. `--without-shear`, `--without-bend`, `--bend`
и `--sheet-ramp` с этим законом неприменимы. Не подбирайте K/G/B при уточнении.
Фактический подшаг и отдельная посадка хранятся в записи. Близость картинок,
нулевая скорость и малая ошибка податливости не принимают физический остаток.

Для визуального разбора с человеком соберите сохранённые формы:

```sh
node scripts/cloth_energy_review.mjs --input=out/acceptance/energy-motion-full-plus.json --out=out/acceptance/energy-motion-review.html
```

Откройте результат через локальный сервер. Стенд не пересчитывает физику:
камера/масштаб общие, время выбирается только среди сохранённых кадров.
Отметьте условия ответа человека и отделите его наблюдение формы от численной
приёмки. Промежутки между кадрами не позволяют оценить быстрые колебания.

Укажите ревизию и грязное/чистое дерево, команду, пакет, режим, условия,
измеряемую величину, порог, итог и ограничение вывода. Если проверку пропустили,
укажите причину. Не переписывайте старое отрицательное измерение после нового успеха.
