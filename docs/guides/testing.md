# Тестирование

## Выбор объёма

На итерациях и перед коммитом запускаются относящиеся к правке проверки в
регрессионном режиме. Полный набор дорог; выбор сокращается по затронутому
поведению, а не по желаемому цвету отчёта.

При изменении совместимости обычного генакера выполняйте
`node tests/gennaker-material.test.mjs`: строгие пробы, явный JS, повреждение
модуля/ABI/постановки и настоящий Worker с двумя частями шага. Затем
`gennaker-simulator.test.mjs` без флага и с `--material-js`, каждый с новым
`--out`; сравнивайте физические результаты отдельно от времени и подготовки.
`node scripts/gennaker_engine_check.mjs --jsc=путь-к-jsc --out=новая-проверка.json`
исполняет ту же регрессию в локальном JavaScriptCore: четыре режима по 60
шагов, прежние критерии, сохранённая оболочка и SHA. Она заменяет только
служебные функции Node, не формулы; проверяет движок, не экран/темп Safari.
После пересборки отдельно проверяйте страницу, сообщения и консоль браузера.

Полный режим (`--full` или `SV20_FULL=1`) нужен при провале регрессии, изменении
отпечатка или риске за пределами проверенной области. Реализация режимов —
`tests/lib/mode.mjs`; режим влияет на густоту сценариев и длительность там,
где он используется, но не отменяет критерии проверки. Передайте `--full`
отдельному тесту; `make test --full` не является командой этого режима.

## Наборы Makefile

| Команда | Состав и смысл |
|---|---|
| `make test` | Сборка пакета, Python-проверки section/bl/panel/milgram/polar/cfd и FAST-проверки JS |
| `make slow` | coupled, upwind, wake, wing |
| `make all-tests` | `test` + `slow`; не включает эталонные `ref` |
| `make ref` | sailforce, upwindforce: сравнение с внешними измерениями |
| `make t-axes` | Пример отдельной Make-проверки |
| `make docs-check` | Локальные ссылки, разделы и доступность документации; без сборки |
| `node tests/gennaker-observables.test.mjs` | Независимая проверка общих измерителей формы/нагрузки |
| `node tests/gennaker-acceptance.mjs` | Совместный диагностический протокол; `--gate` требует полную приёмку |
| `node tests/gennaker.test.mjs` | Генакер отдельно; не входит в FAST/SLOW |
| `node tests/planing.test.mjs` | Глиссирование отдельно; не входит в FAST/SLOW |

FAST: `axes buoyancy membrane cloth vlm waves ocean wind terrain replay physics
sailcoeffs kernel`. Python-проверки требуют `.venv` с нужными библиотеками.
Makefile — источник состава наборов: обновляйте эту таблицу при его изменении.
Не используйте `make -j` для тяжёлых исследований и CFD.

поля настоящего отдельного потока, отказ команды и владение снимком реакции.
Браузерный `cloth_rigid_sail_review.mjs` измеряет собственный Worker,
не FPS основной сцены. [Команды и границы](simulation.md#полный-парус-на-свободной-опоре).

**Регрессия:** сохраняются заданные свойства модели. **Сопоставление с
измерением:** модель ограничена независимыми данными. **Диагностический
эксперимент:** локализована причина или записан отрицательный вариант.
Эти результаты не подменяют друг друга.

Состояние `t-cfd` на 2026-09-30: 20 существующих отказов группировки серий;
[условия и повтор исходной ревизии](../research/cfd.md#состояние-проверки-инфраструктуры).
Не считайте весь набор успешным по одному `validate`.

Красный `ref` означает расхождение с эталоном, которое нужно объяснить.
Диагностика может штатно печатать отрицательный результат; её код выхода и
пороги должны быть указаны в записи. Не добавляйте такой опыт в обязательную
зелёную батарею без принятого смысла проверки.

## Приёмка нового режима генакера

Сохраняются существующие ограничения `Γmax < 300` и шагового скачка общей тяги
`≤ 5 %` в проверках, которые их задают. В `gennaker.test.mjs` есть и другие
критерии, включая размах на установившемся режиме; они не тождественны шаговому
скачку. Не переносите один процент из одной проверки в другую.

Единый [контракт совместной приёмки](../reference/gennaker-acceptance.md)
задаёт станции, фазы нагрузки, окна, сценарии и формат результата.
`gennaker-observables.test.mjs` проверяет сами измерители; это не приёмка физики.
`gennaker-acceptance.mjs` запускается отдельно и не включён в FAST/SLOW.

Нужны оба направления ветра, несколько соседних режимов и начальных состояний,
парный манёвр 140°/6 м/с/8.5→9.0→8.5 м, глубокий курс 150°/8.5→9.2 м,
сходимость ткани и времени. Заворот измеряется по геометрии, а не по добавленной
анимации. Максимум скорости не обязан находиться внутри текущей шкалы верёвки.

Для чистого переноса кода:

```sh
node scripts/golden.mjs > /tmp/sv20-before.txt
# После правки:
node scripts/golden.mjs > /tmp/sv20-after.txt
diff -u /tmp/sv20-before.txt /tmp/sv20-after.txt
```

Отпечаток включает генакер. Сохраняйте одинаковый физический пакет и условия;
совпадение не доказывает достоверность, а только неизменность проверенных сценариев.

## Как записать проверку

Для изолированной механики генакера:

```sh
node tests/cloth-mechanics.test.mjs
node tests/cloth-frozen-aero-grid.mjs --tack=1 --sheet=9 --iter=40 --fixed-load --cols=17,33 --mechanics --edges --attachment-paths --rigid-board --out=out/acceptance/mechanics-full-plus.json
```

Контроли: отдельные `--without-shear`, `--without-bend`, затем оба флага;
другая сторона — `--tack=-1`. Уточнение — `--iter=160` и `--cloth-hz=120` или `240`.
Поддержаны 30/60/120/240 Гц; 30 и 60 внешних кадров дают одинаковый
внутренний шаг 1/60 с, а 120/240 — фактические шаги 1/120 и 1/240 с.
Подшаг при 30/60 кадрах одинаков, поэтому проверять его нужно по JSON,
а не по частоте внешнего цикла. `--mechanics` отделяет посадку от длительности;
для прежнего отсчёта не передавайте этот флаг. `--seconds=1` пригоден для
короткой проверки инструмента, не для приёмки установившегося паруса.

Для нового заданного материала полным уравнением вместо прежнего проектора:

```sh
node tests/cloth-implicit-motion.test.mjs
node tests/cloth-implicit-invariants.test.mjs
node tests/cloth-frozen-aero-grid.mjs --tack=1 --sheet=9 --iter=40 --fixed-load --cols=9,17,33 --mechanics --rigid-board --energy-material --implicit-motion --hold-cut-clew --cut-nesting --seconds=30 --out=out/acceptance/implicit-motion-full-plus.json
```

`--grids=11x9,21x17,41x33` задаёт пары «строки × столбцы» вместо
`--cols`; без него прежние 11 строк сохраняются. `--cut-nesting` сверяет
общие узлы по обоим направлениям. Середина измеряется на половине высоты,
а не на неизменном номере строки. Сначала проверьте исходный вход:

```sh
node tests/cloth-frozen-aero-grid.mjs --tack=1 --sheet=9 --fixed-load --grids=11x9,21x17,41x33 --rigid-board --hold-cut-clew --cut-nesting --audit-input --out=out/acceptance/frozen-input-height-plus.json
```

`--audit-input` готовит штатный крой и измеряет силу, три момента в осях
рига вокруг начала координат, массу и понодальные нагрузки до движения.
Решатель не вызывается; такую запись нельзя выдать за проверку движения.
Флаг несовместим с `--mechanics`, `--energy-material` и изменением шкота.
`--fixed-load` сохраняет давление во времени внутри одного опыта, но само
по себе не гарантирует одинаковое поле при изменении сетки по высоте.

`--shared-input` задаёт отдельный контрольный опыт: на неподвижном крое 11×9
снимаются давление, вес, масса и сопротивление движения. Из них строится одно
билинейное поле в долях высоты/ширины, затем интегрируется на каждой вложенной
сетке. Общие сила и масса сохраняются; момент проверяется отдельно вместе
с геометрией. Перераспределение меняет исходные узловые числа даже на 11×9,
поэтому этот опыт нельзя склеивать с прежними сериями как ту же постановку.

```sh
node tests/cloth-shared-input.test.mjs
node tests/cloth-frozen-aero-grid.mjs --tack=1 --sheet=9 --iter=40 --fixed-load --grids=11x9,21x17 --mechanics --rigid-board --energy-material --implicit-motion --hold-cut-clew --cut-nesting --shared-input --seconds=1 --out=out/acceptance/implicit-shared-space-smoke.json
```

Поле, порядок его 16 компонент и происхождение записаны в JSON. Крой,
K/G/B, затухание 6 с⁻¹ и допуски полного решения не меняются. При уточнении
массы планка заново получает сумму `Σm_i t_i²`, а не прежнюю массу конца.
Короткая серия проверяет подключение; она не принимает пространство или
равновесие. При продлении общего входа до 5 с на 21×17 есть известные отказы
доведения при пределах 40 и 80; условия сохранены в исследовании материала.

При отказе стенд сохраняет `phase: failed`, сообщение, фазу и время попытки,
проверку исходников и последнее завершённое состояние в `failedGrid`.
`results` содержит только завершённые сетки. Последнее состояние не является
конечным принятым результатом. Проверка записи отказа: та же команда с
`--iter=1` и новым именем результата должна завершиться с кодом 1 при посадке.
Генератор завершённых форм отклоняет такие записи.

Перед пространственной серией проверяйте переход от границы к первым
внутренним строкам. Текущий крой имеет известный отрицательный результат:
расстояние спереди и в середине низа не стремится к нулю с шагом высоты.
Его снимают без решателя движения; общий узел сам по себе недостаточен:

```sh
node tests/cloth-cut-height.mjs --out=out/acceptance/cut-height-continuity.json
node tests/cloth-cut-height.mjs --rows=11,41,161 --out=out/acceptance/cut-height-review.json
node scripts/cloth_energy_review.mjs --input=out/acceptance/cut-height-review.json --out=out/acceptance/cut-height-review.html
```

Явный новый крой задаётся `--cut=continuous`; команды чистого аудита и
сравнения с прежним вариантом — в [исследовании материала](../research/cloth-material.md#непрерывное-согласование-границ-исходного-кроя).
На замороженном стенде соответствующий флаг — `--continuous-cut`.
Он требует неподвижных углов, постоянной нагрузки, жёсткой планки и либо
`--audit-input`, либо `--implicit-motion`. При `--shared-input` исходное поле
11×9 также строится на новом крое. Поэтому это отдельная постановка,
её нагрузку нельзя подменять входом прежней серии.

Аналитический контроль профиля задаётся `--cut=continuous-analytic`,
в замороженном опыте — `--continuous-cut --analytic-cut-profile`.
Все прежние границы сохранены, внутренний максимум находится по производной
кривой. Старый дискретный поиск остаётся отрицательным контролем; в записи
кроя есть `profileScan` области найденного скачка, независимо от сетки.
`node tests/cloth-cut-refinement.mjs --input=крой.json --out=измерение.json`
сравнивает новые узлы с треугольниками прежней сетки в тех же u/v,
сохраняет происхождение и проверяет общие узлы. Это измерение, не порог G2.

`node tests/cloth-cut-profile-audit.mjs --out=out/acceptance/cut-profile-audit.json`
разделяет влияние числа делений и способа поиска максимума, проверяет
сохранение всех краёв и измеряет достижение целевых параметров профиля.
Временные варианты живут только в памяти; исходники, допуски и пакет
не меняются. Не считать удачный локальный контроль приёмкой всего паруса.

`node tests/cloth-profile-reachability.test.mjs` проверяет независимую
алгебраическую оценку полного кубического семейства: известные пределы,
внутренние экстремумы и другие прямые кривые. Аудит профиля сохраняет
полный диапазон каждого заданного сечения, включая предел нулевой ручки.
Недостижимость вне этого диапазона не исправляется расширением поиска.

Составной контроль задаётся `--cut=continuous-joined`, в замороженном опыте —
`--continuous-cut --joined-cut-profile`; одновременно выбирать аналитический
и составной профили нельзя. `node tests/cloth-joined-profile.test.mjs`
проверяет независимые известные кривые, углы, максимум, две производные
и условия существования на 1001 уровне. Аудит кроя записывает `sections`
через общий `rowShape(...,true)` на пяти долях рядов: это сечения после
согласования краёв, а не доказательство сохранения четырёх заданных параметров.

`node tests/cloth-cut-boundaries.mjs --out=out/acceptance/cut-boundaries.json`
сопоставляет три непрерывных варианта с одними краями. Прямая верхняя планка
проверяется независимо по её концам; 513 точек поверхности измеряются общим
`rowShape` через адаптер с прежним контрактом индекса ряда. Записываются
обе крайние формы и предел у верха. Проверка округления 10⁻¹² м не принимает
физику и не меняет допуски движения. Входы и пакет защищены отпечатками.

`cloth-motion-refinement.mjs --input=запись --input=другая-запись --out=сравнение.json`
сопоставляет движения на вложенных сетках в общих сохранённых кадрах. Нужны
завершённые прогоны с одним полем, условиями, материалом, шагом и
отпечатками модели; несовпадающие исходники, изменённые записи и отказы
отклоняются. Измеряются расстояния/RMS в общих узлах без совмещения или
интерполяции времени; отдельно те же пары измеряются на одном фиксированном
наборе самой малой сетки, чтобы смена числа проб не влияла на сравнение.
`cloth-motion-refinement.test.mjs` использует известный
сдвиг 3–4–5 и отклонение только одного угла. Это проверка измерителя, не G2.
Полученный файл сохраняет все исходные ревизии/отпечатки, формы и свой вид
происхождения; `cloth_energy_review.mjs` показывает их в условиях стенда.
Каждый исходник модели дополнительно сверяется с Git-коммитом записанного
прогона и текущим файлом, пакет — по SHA256. Общая отметка `dirty:true` из-за
независимых файлов не запрещает измерение при таком совпадении; она сохраняется
в `sourceRecords`. Незакоммиченная физическая модель этим правилом не допускается.

Контракт `cutAt(rf,t)` — выборка узлов кроя по индексу ряда;
`cutSurfaceAt(u,v)` — аналитическая опытная поверхность по долям ширины/высоты.
`cloth-cut.test.mjs` проверяет оба контракта независимо плоским квадратом
в узлах. При изменении выборки требуйте совпадения движения/нагрузки и
энергии, а показания формы сравнивайте отдельно от исправленного наблюдения.

Генератор распознаёт `config.cutOnly`: он показывает только исходный крой,
без фиктивного движения или нагрузки. Вопросы и подписи отличаются от
стенда наполнения. Визуальное мнение не отменяет численного дефекта границы.
`--display-grids=11x9,21x17,41x33` выбирает карточки из существующей записи
без пересчёта геометрии. Все запрошенные сетки должны присутствовать во
всех входах; исходный SHA-256 и фактически показанные размеры сохраняются
в условиях страницы. Уточнение обеих осей видно в заголовке и размерах;
оно не означает одинаковых физических размеров треугольников у всех краёв.

`--energy-material` требует неподвижных углов; прежние мягкие связи и дальние
пределы отключены. Энергия и остатки — в `energyMotion`; прежний наблюдатель
не получает выдуманных реакций. `--without-shear`, `--without-bend`, `--bend`
и `--sheet-ramp` с этим законом неприменимы. Не подбирайте K/G/B при уточнении.
Фактический подшаг и отдельная посадка хранятся в записи. Близость картинок,
нулевая скорость и малая ошибка податливости не принимают физический остаток.

Без `--implicit-motion` сохранён приближённый вариант отрицательного контроля;
его известные движения проверяет `cloth-energy-motion.test.mjs`. Полное
уравнение проверяется двумя командами выше. `--iter` задаёт предел
внешних итераций, а доведение — независимые допуски сил, длины, знака реакции
и её произведения на свободную длину из `IMPLICIT_TOLERANCES`. Недоведённый шаг
отклоняется; его нельзя принять по близкому силуэту или ослабить допуски.
Мягкие множители вычисляются из энергии после решения; нулевая податливость
этой ветви — тождество. Контроль движения — физический силовой остаток.

Прямые предельно натянутые кромки проверяются отдельно:
`node tests/cloth-implicit-invariants.test.mjs --straight-control`. Для текущего
решателя ожидается отказ с кодом 1: поперечная реакция не представляется
конечными множителями обычных ограничений длины. Это отрицательный контроль
постановки кромок, не зелёная регрессия; [условия](../research/cloth-material.md).

Для визуального разбора с человеком соберите сохранённые формы:

```sh
node scripts/cloth_energy_review.mjs --input=out/acceptance/implicit-motion-full-plus.json --input=out/acceptance/implicit-motion-full-minus.json --out=out/acceptance/implicit-motion-review.html
```

Откройте результат через локальный сервер. Стенд не пересчитывает физику:
камера/масштаб общие, время выбирается только среди сохранённых кадров.
Отметьте условия ответа человека и отделите его наблюдение формы от численной
приёмки. Промежутки между кадрами не позволяют оценить быстрые колебания.

Укажите ревизию и грязное/чистое дерево, команду, пакет, режим, условия,
измеряемую величину, порог, итог и ограничение вывода. Если проверку пропустили,
укажите причину. Не переписывайте старое отрицательное измерение после нового успеха.

`cloth-material-buffers.test.mjs --baseline=ревизия --out=новая-проверка.json`

при запрещённых запросах к старым каталогам. Это настольный Chrome.

`node tests/gennaker-step.test.mjs` проверяет контракт фаз: ожидание ответа
ткани, неизменность выбранного плана, запрет преждевременного/повторного

При переносе фаз сравнивайте точные физические отпечатки до/после;
`gennaker-simulator.test.mjs` вызывает ядро шага с прямым решателем,
а `gennaker-metrics.test.mjs` и проверки сессии/записи — с настоящим Worker.

`node tests/gennaker-simulator.test.mjs --out=новая-запись.json` проверяет
обычный Rig/Boat и новую ткань обеих сторон, передачу трёх моментов,
сохранение нагрузки грота и выделение сухой массы. Длительность задаётся
`SV20_COUPLING_STEPS` (по умолчанию 60). Для длительного контроля используйте
300. Регрессия охватывает рабочие более полные курсы; `--full` добавляет
более острый старт с ходом, у которого есть сохранённые отказы. Проверка
итерирует реальный расчёт, не является тестом вида UI.
Смена входного маршрута проверяется `live-sail-entry.test.mjs` с двумя
исходными постановками и новым `--out`. Правки Boat дополнительно требуют
`make t-physics`, `sail-load.test.mjs`, `boat-cloth-load.test.mjs`; формат
дампа — `replay.test.mjs`. Точный повтор новой ткани проверяется отдельно ниже.

`node tests/gennaker-state.test.mjs --out=новая-запись.json` проверяет снимок
отдельного решателя: оба борта и WASM/JS, JSON, принятое дробление до 1/240 с,
68 отказов до изменения состояния и настоящий Worker с запретом снимка
между двумя частями. `gennaker-simulator.test.mjs` дополнительно восстанавливает
второй расчёт в середине каждого из четырёх режимов, подаёт ему те же живые
воздушные нагрузки и сравнивает все ответы продолжения точно. Сравнивайте
`physicalSha256` с прежним этапом. Это не полное восстановление Boat/Rig
или сцены и не проверка переносимости между разными движками браузера.

`node tests/rig-air-state.test.mjs --out=новая-запись.json` проверяет точную
память воздуха: начальные состояния с генакером/без него, рост и заполненный
след, JSON, оба борта, `wakeSlice` 1/3, смену команд и выключение/возврат следа.
Требуются точное продолжение, сохранение владельцев буферов и отказ до
изменения состояния при 144 подменах. Сброс удержанных скоростей — отдельный
отрицательный контроль, без ослабления критерия равенства.
`node tests/gennaker-restart.test.mjs --out=новая-запись.json` и тот же запуск
с `--material-js` восстанавливают сборку компонентов воздуха/ткани/лодки
с середины отпускания шкота в восьми режимах: ветер 4/6 м/с, оба борта,
`wakeSlice` 1/3, известный вход воды. Все ответы/состояния продолжения должны
совпасть точно. Эта проверка собирает состояние в тесте; публичную загрузку
целого снимка обычным UI проверяет `gennaker-session.test.mjs` ниже.
В `gennaker-metrics.test.mjs`
проверяется запись исходного входа воды при его смене во время Worker.

`node tests/gennaker-session.test.mjs --out=новая-запись.json` и повтор с
`--material-js` используют публичные `capture/restore` обычного адаптера:
JSON, пустое состояние, четыре сочетания борта/`wakeSlice`, продолжение 60
шагов до конца сценария, снимок во время шага и 96 атомарных отказов на
режим материала, включая неисправный новый Worker. Дополнительно проверяются
обычные команды без сценария, грот/руль/шкот, уборка и старый дамп без ткани.
`gennaker_session_browser_check.mjs --out=новый-отчёт.json` требует локального
сервера и `SV20_PLAYWRIGHT_MODULE`: собранная WebGPU-сцена, API, настоящая
кнопка сохранения/серверная загрузка/drop, середина манёвра, игровой экран
390×844 и обычный URL с управлением. Это настольный браузер, не мобильный бюджет.

`node tests/gennaker-recording.test.mjs --out=новая-история.json` и повтор с
`--material-js` проверяют точные команды/воду, оба борта/`wakeSlice`, подмены,
включение/выключение записи без изменения физики и 665 шагов с вытеснением
начала кольца, подъёмом/уборкой и сменой ветра/порывов/управления. Результаты каждого шага и
полное конечное состояние должны совпасть точно. К браузерной команде выше
добавьте `--replay=1 --ring=1 --dump-out=новый-снимок.json`, затем проверьте этот
реальный снимок через `node scripts/replay.mjs новый-снимок.json`.


## Первые измерители обычной ветки М0

`node tests/gennaker-metrics.test.mjs --out=новая-запись.json` проверяет
часы на известных интервалах, исключённые фазы, учёт неудачного родителя
и дочерних попыток, настоящий Worker и обычный контроллер. Полные 90
состояний с профилем/без него при разных частотах кадров должны совпасть
точно; отдельно проверены второй борт/wakeSlice=3 и перезапуск. DOM/сеть
адаптированы для Node: это не браузерная сцена и не мобильный профиль.
Затем запускаются связанные `gennaker-material` и `gennaker-simulator`.
Последний сохраняет `physicalSha256` всех полных состояний, отдельно от
времени и диагностических полей. [Команды браузера](simulation.md#измерение-обычной-ветки-м0).


Для расписания ранней М3 `gennaker-metrics.test.mjs` сравнивает полные
состояния frame/message на 30/60/120 заданных вызовах, допуск по накопленному
времени и восстановление UI после настоящего отказа Worker. Для полной сцены
используется [браузерный инструмент](simulation.md#ранняя-м3-расписание-без-ожидания-кадра):
замороженный исходный граф, три чередующиеся пары, реальные WebGPU и
скачивание. Числа разных входов воды не приравниваются к строгому повтору.


`node tests/cloth-solver-profile.test.mjs` проверяет известные вложенные
интервалы, отказ, неизменность ответа и полный численный повтор после
вынужденного дробления. `gennaker-metrics.test.mjs` проверяет доставку
профилей обеих частей и отказа через настоящий Worker/канал.
`node tests/gennaker-solver-profile.test.mjs --out=новый-профиль.json` запускает
три чередующиеся пары с часами/без них на обоих бортах, `wakeSlice=3`.
Каждый прогон имеет 90 шагов лодки, 80 с тканью; первые 10 шагов ткани
исключены из измеряемого окна. Полные физические снимки должны совпасть.
Проверочный Node Worker отдельно измеряет CPU своего потока от входной
команды до отправки ответа; это не часы браузера. Повтор с
`--material-js --pairs=1` проверяет совместимость, а не надёжную оценку цены.
[Команды разбора и браузера](simulation.md#подробный-профиль-решателя).
