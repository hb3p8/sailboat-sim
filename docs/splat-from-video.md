# Берег из видео: реконструкция сплатами

План Б к акватории. Карта из открытых данных даёт верную геометрию, но берег по
ней не узнаётся — силуэт правильный, а места нет. Замысел: восстановить облик
берега по съёмке с дрона и расставить куски по карте.

Здесь записано, что вышло на первом пролёте, какими числами это меряется и на
чём ушло время. Конвейер работает целиком на этой машине; **вопрос о годности
для симулятора остаётся открытым**, и почему — в конце.

Всё считанное (видео, кадры, маски, облака) не коммитится: сотни мегабайт и
чужая работа под обычной лицензией YouTube. Откуда что взято —
[data/video/SOURCES.md](../data/video/SOURCES.md).

---

## Конвейер

```bash
python3 scripts/video_shots.py data/video/6LTJFLL0pAQ.webm --list
python3 scripts/video_shots.py data/video/6LTJFLL0pAQ.webm --shot 1 --fps 6 --width 1600
bash    scripts/sfm.sh         data/video/shot01
python3 scripts/video_masks.py data/video/shot01 --check 0025.jpg
brush   data/video/shot01/ds --sh-degree 0 --max-splats 600000 --total-train-iters 7000
python3 scripts/splat_orient.py <ply> --poses data/video/shot01/sparse/1 --out <ply-up>
brush   <ply-up> --with-viewer
```

Обучение — [Brush](https://github.com/ArthurBrussee/brush) (Rust + wgpu, MCMC),
единственный из опробованных, который считает на Apple Silicon без плясок.
`msplat` собирается только с отдельным многогигабайтным компонентом Xcode
(Metal Toolchain), а Python-биндинги у него падают на nanobind;
Triangle Splatting+ — CUDA-only.

---

## Что получилось

Съёмка: «Нижний Новгород с высоты», 4K, 291 с, **смонтирована из 31 плана**,
почти все по 7.4 с. Первый план — Кремль и откос, 7.6 с, 46 кадров после
прореживания до 6 к/с и отбраковки смазанных.

| | |
|---|---:|
| Кадров зарегистрировано | 46 из 46 |
| Точек в разреженном облаке | 4 239 |
| Длина трека | 24.6 |
| Невязка перепроецирования | 0.50 px |
| Фокусное, к которому сошлось | 1632 px, то есть 52° по горизонтали |
| Высота съёмки | ~350 м |
| База по всему плану | ~70 м |
| **Угол триангуляции по всей базе** | **11.2°** |
| Прямолинейность траектории | 1.00 |
| Масштаб | 1 единица ≈ 5.3 м |
| Протяжённость сцены вдоль полёта | 1137 м |

Обучение: 7000 итераций, ~12 минут на MacBook Air M5 (8 ядер GPU, 16 ГБ).
Сферические гармоники нулевой степени — зависимость от направления не нужна.

| | без масок | с масками |
|---|---:|---:|
| Сплатов | 501 150 | 468 875 |
| Файл | 27 МБ | 25 МБ |
| PSNR по всему кадру | 23.02 дБ | 18.32 дБ |
| **PSNR по обучаемой части** | **23.78 дБ** | **24.07 дБ** |

Маски выбрасывают небо (18.8% кадра), воду (5.0%) и вжжённые титры (5.4%).

**Про две колонки PSNR.** Разница 23.02 → 18.32 — целиком артефакт измерения:
модель с масками небо и воду не восстанавливает вовсе, а ошибка считалась и по
ним. На пикселях, которые действительно участвуют в обучении, маски дают
+0.3 дБ. Сравнивать надо по маске, иначе вывод получается ровно
противоположный правде.

Для ориентира: хорошие результаты 3DGS на эталонных наборах — 27–33 дБ. То
есть 24 дБ это «рабочее, но небогатое», и получено на 46 кадрах с 11° угла.

## Что не получилось

**Ожидание, что мусор мешает, не подтвердилось.** Маски убрали 6% сплатов — это
не пелена из хлама, это немного. Полосы и смазы по краям и вверху кадра остались
и после маскирования: они не от неба, а от дальнего плана, который дрон видел с
малым параллаксом.

Остаётся вторая гипотеза, та же, что была до начала: **с направления, откуда
смотрит лодка, данных нет.** Дрон шёл по идеальной прямой на трёхстах
пятидесяти метрах; фасады, обращённые к воде, он видел только сверху под
скользящим углом и ни разу сбоку. Облёта нет — значит закрытое не раскрывается
нигде.

Проверить это осталось глазом в просмотрщике: отойти вбок от прямой полёта и
опуститься к урезу. Числа сюда не дотягиваются, а отладочный рендер
(`splat_render.py`) для такого слишком груб — он кладёт квадраты вместо
анизотропных гауссиан и очерняет результат.

## Грабли

Записаны потому, что каждая стоила времени, а по числам ни одна не видна.

**Порог угла триангуляции больше, чем есть в съёмке.** Штатный
`init_min_tri_angle` у COLMAP — 16°, а во всём семисекундном плане угла больше
11.2° не бывает. Ни одна пара порог не проходит; перебор их всех — восемнадцать
минут молчания и `No good initial image pair found`. Считается на пальцах до
запуска: база 70 м при дальности 350 м. **У всех 31 плана будет то же самое.**

**COLMAP 4.1 переименовал опции** против всех руководств в сети:
`SiftExtraction.use_gpu` → `FeatureExtraction.use_gpu`, `SequentialPairing` →
`SequentialMatching`, `ba_global_images_ratio` → `ba_global_frames_ratio`.
Рабочие имена зафиксированы в `sfm.sh`.

**Вертикали нет ни у кого, и все ошибаются по-разному.** Brush пишет свою оценку
в комментарий PLY — на этой съёмке она промахнулась на **87°**, и просмотрщик
показывал сцену лежащей на боку. Оценка по центроиду облака (центроид смещён
небом и застройкой) ошибается на **58°**. Рабочая — по камерам: у камеры без
крена вектор «вправо» горизонтален, траектория дрона горизонтальна, вертикаль
перпендикулярна обоим (`splat_orient.py`).

**Циклическая проверка.** «Траектория горизонтальна при такой вертикали» —
ничего не значит: вертикаль строится перпендикулярно траектории, ноль выходит по
построению. Выглядит убедительно, не проверяет ничего. Настоящая ошибка
вертикали здесь около **3°**, и видна она только тем, что геометрический
горизонт расходится с видимым на картинке.

**Два детектора масок пришлось переделать, и оба провала нашлись глазами.**
Титры сначала искались по малому временно́му отклонению яркости — набрали 27%
кадра неподвижной далью (за 7.6 с дальний план почти не смещается) и не взяли
саму надпись, потому что она проявляется и гаснет. Дорост неба рвался на
облаках: они ярки, но текстурны, и не проходили условие гладкости. Ни то, ни
другое по сводным числам не заметно — только по наложению, которое рисует
`--check`.

**Вжжённые титры вообще стоит искать заранее.** Надпись неподвижна в экранных
координатах, камера движется — реконструкция честно поместит её висящей в
воздухе.

## Что дальше

1. **Перебрать планы.** Из 31 наверняка есть более низкие проходы вдоль воды.
   Отбирать по высоте съёмки, а не по красоте кадра.
2. **Съёмка с борта.** Виды с высоты глаза дают ровно те ракурсы, из которых
   потом смотрят, и снимают вопрос с лицензией заодно.
3. **Привязка к карте** — когда будет что привязывать. Способ описан в
   [terrain-in-sim.md](terrain-in-sim.md): плоскость воды даёт три степени
   свободы, береговая черта из OSM — остальные четыре.
